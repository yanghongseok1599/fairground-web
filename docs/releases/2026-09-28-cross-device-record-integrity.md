## 조회 중 기록 보존

- `createMatchLiveRefresh`로 경기 목록·이벤트 조회를 직렬화했다. 이전 화면에서 시작된 늦은 응답은 구독 해제 후 적용하지 않는다.
- 이벤트 조회 실패를 성공한 빈 기록으로 바꾸지 않는다. 실시간 화면은 마지막으로 확인한 경기·이벤트를 보존하고, 단건 경기 조회 실패는 호출 화면에 실패로 전달한다.
- 실시간 연결 재가입, 온라인 복귀, 화면 복귀 및 보이는 화면의 5초 간격 재조회로 놓친 변경을 다시 읽는다. 조회 재시도는 경기 이벤트를 생성하지 않는다.

## DB 오류 재현과 준비된 수정안

**운영 DB 반영은 사용자 승인 대기다. 아래 DB 검사는 운영 구조를 복원한 로컬 DB에서 통과한 결과이며, 운영 수정 완료를 뜻하지 않는다.**

운영 스키마의 실제 역할 속성·함수 소유자·권한을 복원한 PostgreSQL 17에서 다음 오류를 재현했다.

1. `end_match`의 `count(*)`는 bigint인데 `compute_card_rating`은 integer를 받는다. 종료 시 함수 선택 오류로 집계 트랜잭션이 실패했다.
2. 출전 명단이 없고 득점 등 이벤트도 없는 MOM 선수는 종료 집계에서 누락됐다.
3. 두 번째 경고가 만든 자동 퇴장이 경고 취소 후에도 남았다.

`20260928010000_match_finalization_regression_fix.sql`은 집계 수의 타입을 맞추고, MOM을 집계 대상에 포함하며, 신규 자동 퇴장에 원인이 된 경고 ID를 연결한다. 경고 취소는 이 연결이 있는 자동 퇴장에만 적용하고 직접 퇴장은 유지한다. 기존 이벤트의 내용이나 회원 기록은 갱신하지 않는다. 과거 자동 퇴장과 직접 퇴장을 추정으로 구분하지 않는다.

- 스키마 전용 백업 573,630바이트, 실제 격리 복원 성공. 회원 행은 복사하지 않았다.
- 운영과 복원본의 공개 스키마 비교 대상 4,547개가 일치했다.
- 변경 검토: 기존 함수 3개 변경, 신규 `source_yellow_event_id` 컬럼·외래키와 관련 컬럼 권한 추가. 기존 객체 삭제 없음.
- 적용 스크립트는 대상 ref, 변경 전후 스키마 해시, 기존 이력 66건 보존, 이벤트 행 수 보존을 검사한다. 진행 중인 경기가 있거나 3초 이내 잠금을 얻지 못하면 중단한다.
- 전체 마이그레이션 이력 불일치는 해결하지 않았다. 운영 `db push`, `migration repair`, linked reset을 실행하지 않았다.

## 동작과 경계

심판이 경기·시계·득점·교체·MOM·종료를 조작한다. 관리자는 같은 상태와 기록을 실시간으로 확인하고 두 화면의 경기를 초기화할 수 있다. 초기화 요청은 심판이 확인 응답을 보내며, 같은 요청의 재전송은 경기를 중복 개설하지 않는다.

동일 역할의 추가 화면은 조작을 잠근다. 심판 재접속·인계 시 관리자의 최신 기록 응답을 기다리고 일시정지 상태로 복원한다. 연결이 끊기거나 동기화가 끝나지 않았으면 조작을 잠근다. 시계는 심판 한 화면에서만 진행한다.

공유 링크는 연습방 참여 수단이며 실제 관리자·심판 계정 권한을 인증하지 않는다. 실제 회원·팀·경기·순위에는 쓰지 않는다. 서버에 결과를 영구 보관하지 않으므로 모두 탭을 닫고 탭 저장도 사라지면 새 경기로 시작한다. 공식 경기의 DB 트랜잭션·RLS·테이블 구독 검증과는 별개다.

전송에는 [Supabase Broadcast](https://supabase.com/docs/guides/realtime/broadcast), 접속 현황에는 [Presence](https://supabase.com/docs/guides/realtime/presence)를 사용한다. 전용 `practice-room-v1:<UUID>` 채널의 가상 데이터만 전달하며 스키마나 환경변수는 변경하지 않았다.

## 배포 소스·환경

직전 운영 소스 906개를 파일별 SHA-1으로 확인해 시스템 임시 폴더에 복원했다. 구현 커밋의 10개 파일만 패치했으며 업로드된 913개 파일이 검증본과 모두 일치했다. 변경 범위는 위 10개와 타입 검사 생성물 `tsconfig.tsbuildinfo`다. 작업 브랜치 전체와 미완료 사용자 변경은 포함하지 않았다. [변경 명세](2026-09-20-shared-match-simulation-manifest.json)를 참고한다.

Supabase 개발/운영 환경과 원격 이력을 읽기 전용으로 확인했다. 기존 이력 불일치는 남아 있다. DB·Auth·Storage·마이그레이션·지속 환경변수는 변경하지 않았으며, 운영 Realtime의 일시적인 연습 메시지만 사용했다.

새 DB 참조는 없다. 배포본의 DB 참조 150개를 2026-09-15 운영 카탈로그와 대조해 누락 0개를 확인했다. 새 카탈로그 전체 조회는 수행하지 않았다. 기존 Production의 `SUPABASE_DB_URL` 미설정 때문에 이번 빌드 한 번에만 `FAIRGROUND_SKIP_DB_PARITY=1`을 전달했고 지속 환경변수나 게이트 코드를 바꾸지 않았다. 원격 설치의 기존 의존성 감사 경고 5건은 남아 있으며 의존성은 변경하지 않았다.

개발 서버·브라우저 검증 공간을 종료하고 생성한 빌드 캐시, 복원 소스, 임시 응답과 로그를 정리했다. 기존 사용자 작업과 의존성을 보존했으며 최종 프로젝트 용량은 2.4GB다.

# 라이브 스코어에 다음 대기 경기 표시

라이브 스코어를 진행 중인 경기, 대기 중인 다음 경기, 최근 결과 순서로 구성했다. 진행 경기에는 점수·경과 시간·중계·상세·출전 명단을, 대기 경기에는 전체 팀명·한국 시간 기준 예정 시간·대회 장소·경기 상세 링크를 표시한다.

## 다음 경기 선택

- 공개된 대진 중 `scheduled` 경기만 대상으로 한다. 비공개 대진과 완료된 대회의 남은 예정 경기는 표시하지 않는다.
- 경기 시간(없으면 생성 시각), 라운드, 생성 시각, ID 순으로 정렬한다. 진행 경기가 있으면 그 이후의 가장 이른 예정 경기 시간대를 선택하고, 아직 시작하지 않았으면 첫 경기 시간대를 표시한다.
- 대회마다 다음 시간대를 선택하며, 같은 시간에 열리는 경기는 모두 표시한다. 실제 스키마에는 구장 번호가 없으므로 조 정보를 구장 번호로 추정하지 않는다.
- 경기 시작·종료·취소·일정 변경·대진 공개 변경은 Realtime과 5초 간격 확인으로 반영한다. 백그라운드에서 돌아오거나 네트워크가 복구될 때도 새로 확인한다.
- 조회 실패는 빈 대진으로 표현하지 않고 재시도 안내와 마지막으로 확인된 기록을 유지한다.

## 유지보수와 검증

`src/features/live-score/` 안에 데이터 조회, 순서 선택, 실시간 연결, 진행 경기 카드, 대기 경기 카드, 명단 패널을 분리했다. `/live` 라우트는 해당 화면을 호출한다. 점수 화면은 경기별 이벤트를 추가 조회하지 않고 경기·대회 두 테이블을 읽는다. DB 스키마 변경이나 운영 경기 생성은 없다.

- 관련 테스트 42개 통과: 비공개 대진 제외, 시작 전 첫 경기, 동시간 경기, 여러 대회, 시작/종료 후 교체, 취소 제외, 시간 미정 정렬, 한국 시간 표시, 조회 실패, 실시간 갱신 및 알림 이동 회귀 검수.
- lint 오류 0개 / 기존 경고 16개, TypeScript 통과.
- 운영 스키마 대조와 `vercel build --prod` 통과. 배포 결과물에 임시 DB 자격증명이 없는지 검사했다.
- 실제 컴포넌트에 합성 경기 데이터를 넣은 화면을 390px 휴대폰 폭과 1280px 데스크톱 폭에서 확인했다. 가로 넘침 없이 진행 경기 1개와 동시간 대기 경기 2개가 표시됐고, 상세 링크가 각각 다른 경기 ID를 사용했다.
- 현재 운영에 경기 데이터가 없어 운영 확인은 빈 상태 표시로 진행한다. 실제 경기 데이터가 생겼을 때의 분류는 합성 데이터 테스트로 검증했다.

[Lazyweb 화면 참고](https://www.lazyweb.com/agentic-search/66291764-2a8f-4e22-9437-2b2a6768c312): FotMob의 경기 상태 구분과 Fixtured의 다음 경기 시간 표시를 참고했다.

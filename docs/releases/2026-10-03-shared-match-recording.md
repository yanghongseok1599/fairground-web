# 실시간 공동 경기 기록 · 2026-10-03

승인된 심판과 관리자가 같은 경기 URL을 열면 점수·이벤트·진행 상태를 공유한다. DB 변경 알림을 받아 최신 서버 응답을 읽고, 누락된 알림은 4초 간격 확인과 재연결 시 조회로 보완한다. 조회에 사진 전체를 포함하지 않는다.

내 기기에 미전송 기록이 있어도 다른 기록자의 입력을 반영한다. 서버 버전과 적용된 작업 UUID로 이미 저장된 기록의 이중 표시 및 늦게 도착한 응답의 덮어쓰기를 방지한다. 기록 내역에 서버 프로필 기준 기록자 이름을 표시한다. 접속자 표시는 참고 정보이며 권한 판정에는 사용하지 않는다.

경기를 시작하거나 재개한 기기가 시간을 저장한다. 다른 심판이 일시정지 후 재개하면 시간 관리가 이전된다. 이전 기기의 지연 타이머는 안전하게 확인 처리하고 새 시간을 덮어쓰지 않는다. 충돌하는 진행 제어는 대기열을 보존하고 확인을 요구한다. 종료된 경기의 새 이벤트를 몰래 합치거나 집계를 다시 적용하지 않는다.

네트워크가 끊기면 기록은 해당 기기에 저장되고 복구 후 전송된다. 연결이 없는 동안에는 다른 기기에 실시간 전파될 수 없다. 같은 실제 사건을 두 사람이 각각 새 기록으로 입력하는 것은 별도 작업이므로 기록자 표시를 보며 역할을 나눠야 한다. 다른 기기의 미전송 기록이 보이면 경기 종료 전에 동기화를 확인한다.

## DB 검증

`20261003040000_shared_match_recording.sql`을 개발과 운영에서 각각 현재 스키마를 복원한 격리 DB에 적용·롤백 검증했다. diff는 새 정의 41개와 기존 RPC 2개 교체이며 기존 RLS·권한을 풀지 않았다. 동일 SQL 해시, 변경 전후 정의, 기존 행과 이력 보존을 검사한 트랜잭션으로 반영했다.

- 운영: 스키마 정의 5,075개 일치, 기존 31개 테이블·회원 132명·경기 12개·이력 75건 보존, 새 이력 1건.
- 개발: 스키마 정의 5,751개 일치, 기존 35개 테이블·회원 15명·이력 13건 보존, 새 이력 1건.
- 두 복원 DB에서 실제 API 역할 테스트 각각 16/16 통과. 별도 계정의 동시 득점, 시간 관리 이전, 지연 타이머, 타인 기록 취소, 중복 종료, 비인가 조회 차단 포함.
- 기기 대기열 테스트 11/11, 관련 화면·캐시 회귀 테스트 35/35, Supabase 안전 테스트 4/4 통과.
- TypeScript 통과. Lint 오류 0개, 기존 경고 16개.

## 실제 브라우저 확인

`localhost`와 `127.0.0.1`의 독립 세션에서 hosted 개발의 합성 관리자와 합성 심판으로 검수했다. 양방향 기록 반영(한 번의 측정 333ms), 오프라인 입력 보존, 복구 후 양쪽 기록 일치, 새로고침 후 유지, 일시정지 공유, 전체화면 기록자 이름을 확인했다. 테스트에서 생성한 합성 경기만 정리했다. 실제 운영 경기는 쓰기 테스트에 사용하지 않았다.

김재민·홍성표 계정은 기존 승인 관리자임을 읽기 전용으로 확인했다. 계정 권한·비밀번호를 변경하지 않았다.

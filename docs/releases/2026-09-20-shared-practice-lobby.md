# 접속 중인 테스트 경기 공유 목록 — 2026-09-20

다른 관리자가 개설한 테스트 경기를 기본 화면에서 찾을 수 없던 문제를 수정했다. `/match-simulation`의 기본 화면을 공유 경기 목록으로 변경하고, 개설 즉시 다른 화면에서도 같은 방을 찾아 심판 또는 관리자로 입장하도록 했다. 혼자 연습은 `?mode=solo`로 분리했다.

사용자가 요청한 대로 접속 중인 방만 공유한다. 심판이나 관리자 한 명이라도 연결돼 있으면 목록에 남고, 마지막 참가자의 퇴장이 Presence에 반영되면 사라진다. 기존에 열어둔 방은 새로고침해야 등록된다. 영구 보관용 DB는 추가하지 않았다.

관리자 여러 명이 같은 점수·시간·기록을 볼 수 있고, 초기화는 먼저 접속한 관리자 한 명이 담당한다. 그 관리자가 나가면 다음 관리자에게 넘어간다. 심판은 기존처럼 한 명만 조작한다. 방 집계, 연결 처리, 목록 UI를 각각 `directory.ts`, `directory-transport.ts`, `lobby.tsx`로 분리했다.

## 배포 범위와 환경

직전 운영 소스 918개를 파일별 SHA-1으로 검증해 시스템 임시 폴더에 복원하고 이번 구현 9개 파일만 패치했다. 업로드된 소스 922개의 해시가 검증본과 모두 일치했고 차이는 이번 9개 파일과 `tsconfig.tsbuildinfo`뿐이다. [배포 명세](2026-09-20-shared-practice-lobby-manifest.json)에 변경 파일을 기록한다. 작업 브랜치의 다른 기능과 미완료 사용자 작업은 포함하지 않았다.

Supabase 환경 분리와 마이그레이션 이력을 읽기 전용으로 확인했다. 기존 이력 불일치는 남아 있다. 스키마·Auth·Storage·Realtime 설정·마이그레이션·지속 환경변수는 변경하지 않았다. 운영 테스트는 가상 경기의 임시 Broadcast/Presence만 사용했으며 실제 경기 기록은 쓰지 않았다.

공개 `practice-directory-v1` 채널은 임시 참가자 ID·방 UUID·역할·입장 시각을 전송하고, 화면은 방 코드와 역할별 접속 인원만 표시한다. 개인 프로필이나 실제 기록은 전송하지 않는다. 이 연습 역할은 실제 계정 권한을 대신하지 않는다.

새 DB 참조는 없다. 배포본의 참조 150개를 2026-09-15 운영 카탈로그와 대조해 누락 0개를 확인했으며 새 카탈로그 조회는 수행하지 않았다. 기존 Production의 `SUPABASE_DB_URL` 미설정으로 이번 빌드에만 `FAIRGROUND_SKIP_DB_PARITY=1`을 전달했다. 게이트 코드나 지속 환경변수는 변경하지 않았다. 기존 의존성 감사 경고 5건은 남아 있고 의존성은 변경하지 않았다.

개발 서버와 검증용 브라우저 공간을 종료하고 생성한 개발 캐시 약 99MB, 배포 복원 폴더, 임시 응답·로그를 정리했다. 기존 사용자 작업과 의존성을 보존했으며 정리 후 프로젝트 용량은 2.4GB다.

# 벤치·필드 양방향 선수 교체 수정 — 2026-09-20

벤치 선수를 눌러 교체를 시작해도 벤치 목록이 표시되고 선택한 벤치 선수를 OUT으로 전달하던 문제를 수정했다. 이제 벤치에서 시작하면 같은 팀의 필드 선수를, 필드에서 시작하면 같은 팀의 벤치 선수를 보여준다. 실제 호출에는 나가는 필드 선수와 들어오는 벤치 선수를 항상 OUT/IN 순서로 전달한다.

`substitution-choices.ts`에 방향 판단·후보·OUT/IN 조합을 분리했다. 팝업 제목으로 투입/퇴장 방향을 설명하고 완료 안내에도 OUT → IN을 표시한다. 교체 후 다시 열면 갱신된 명단으로 후보를 만든다. 공식 경기와 테스트 경기의 공통 운영 화면에 적용했으며 RPC와 DB 로직은 변경하지 않았다.

## 배포 범위와 환경

직전 운영 소스 916개를 파일별 SHA-1으로 검증해 시스템 임시 폴더에 복원하고 이번 구현의 3개 파일만 패치했다. 업로드된 918개 파일의 해시가 검증본과 모두 일치했고 차이는 해당 3개 파일과 `tsconfig.tsbuildinfo`뿐이다. 작업 브랜치의 다른 기능과 미완료 사용자 작업은 포함하지 않았다. [배포 명세](2026-09-20-bidirectional-substitution-manifest.json)에 파일 변경을 기록한다.

Supabase 환경 분리와 마이그레이션 이력을 읽기 전용으로 확인했다. 기존 이력 불일치는 남아 있다. DB·Auth·Storage·Realtime·마이그레이션·지속 환경변수는 변경하지 않았고, 사용자 공동 테스트방은 조작하지 않았다.

새 DB 참조는 없다. 배포본의 참조 150개를 2026-09-15 운영 카탈로그와 대조해 누락 0개를 확인했으며 새 카탈로그 조회는 수행하지 않았다. 기존 Production의 `SUPABASE_DB_URL` 미설정으로 이번 빌드에만 `FAIRGROUND_SKIP_DB_PARITY=1`을 전달했다. 게이트 코드나 지속 환경변수는 변경하지 않았다.

기존 의존성 감사 경고 5건은 남아 있고 의존성을 변경하지 않았다. 개발 서버·검증용 브라우저 공간을 종료하고 생성한 빌드 캐시 약 99MB, 운영 소스 복원 폴더, 임시 응답·로그를 정리했다. 기존 사용자 작업과 의존성을 보존했으며 정리 후 프로젝트 용량은 2.4GB다.

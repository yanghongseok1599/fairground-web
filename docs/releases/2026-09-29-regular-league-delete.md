# 2026-09-29 정규 리그 삭제와 단일 구장 일정 통일

사용자가 `2026 정규 리그` 삭제를 명시적으로 요청했다. 대상은 `700a0000-0000-0000-0000-000000000001` 한 건이다.

운영 조회 결과 대상 대회의 경기는 0건, 대회 생성 활동 이력은 1건, 참가비 기록은 2건이었다. 연결 기록도 삭제됨을 사용자에게 알리고 전체 대상 행과 관련 행을 보호된 로컬 파일에 백업했다.

새 운영 public/auth/storage/마이그레이션 스키마 덤프를 PostgreSQL 17 격리 DB에 복원했다. 원본 스키마 해시 일치, 합성 대회·참가비의 cascade 범위, 다른 대회·유료 참가비·경기 보존, 트랜잭션 롤백, 실행 직전 추가된 경기의 삭제 거부를 검증했다.

운영에서는 대상 대회·연결 행을 잠그고 백업과의 전체 행 일치를 검사한 뒤 이름과 ID가 일치하는 대회 한 건만 삭제했다. 스키마·마이그레이션 이력 68건은 바꾸지 않았다.

- 삭제: 대회 1건, 연결된 생성 이력 1건, 연결된 참가비 기록 2건.
- 보존: `2026 1필드`, 새 편성 경기 12건의 전체 행, 나머지 참가비·선수·팀·사진 등 25개 보호 테이블.
- 커밋 후 읽기 전용 트랜잭션으로 삭제 및 12경기 보존을 재확인했다.
- 증거·복구 자료: `tmp/league-delete-guide/schema-before.dump`, `before.json`, `rehearsal.json`, `delete-receipt.json` (Git 제외).

이 작업은 대상 대회에 한정된 일회성 삭제이며 다른 대회 삭제 권한으로 확대하지 않는다.

## 단일 구장 일정 확정

사용자가 “기존가이드 한구장으로 한다”로 운영 기준을 확정했다. 기존 가이드의 A구장 한 면, 조별 12경기 10:00–14:00, 순위결정전 8경기 14:00–16:40를 유지한다. 경기 12분과 전환 8분으로 한 슬롯은 20분이며 점심 슬롯은 별도로 두지 않는다. 실내구장은 챌린지에 사용한다.

확정 시드는 별도 `public/cup-ops/team-seeds.js`에서 관리한다. 운영가이드의 조 편성, 대진, 쉬는 팀에 실제 팀명을 표시하고 원래 시드 코드도 함께 제공한다. 순위결정전의 출전팀은 조별 순위 및 준결승 결과로 확정한다.

`src/lib/group-fixture-timetable.ts`는 한 구장에서 조별로 번갈아 출전하는 순서를 정의한다. 자동 경기 생성과 큐시트 미리보기가 같은 함수를 사용한다. 관리자는 한 구장과 조별 구장 중 선택할 수 있으며 기본값은 한 구장·10:00·점심 없음이다. 실제 구장은 기존 `tournaments.groups` JSON의 선택적 `court` 속성에 저장한다. 새 DB 컬럼이나 마이그레이션은 필요하지 않다.

운영 조별 12경기 수정 계획은 상대 팀 쌍과 ID를 보존하고 홈/원정 방향, 경기 번호, 시작 시간을 가이드와 일치시킨다. 기존 조 편성·순위표에 `court: A구장`만 추가한다. 전체 대상 행이 백업과 같은지, 모두 미진행이고 연결 기록이 없는지 트랜잭션에서 검사한다. 다른 테이블과 대상 밖 대회·경기 전체 행도 보존 여부를 검사한다. 격리 DB에서 합성 12경기 수정, 롤백, 동시 변경 거부를 검증했다.

검증: 가이드·자동 생성·저장 큐시트의 12경기 상대/순서/시간/구장 일치, 팀별 3경기, 시각 중복 없음, 공통 점심과 크기가 다른 조의 순차 편성 테스트. 기존 조별 구장 테스트도 유지한다. 모바일 390px에서 8팀과 20경기 표를 확인했다.

일정 수정 증거·복구 자료: `tmp/single-court-release/` (Git 제외). 기존 복원 가능한 스키마 백업과 현재 운영 스키마의 해시 일치를 다시 검증했으며 전체 이력 불일치에 대한 기존 보호 조치는 유지한다.

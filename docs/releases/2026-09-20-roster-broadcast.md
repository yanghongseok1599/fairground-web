# 전체 선수 빠른 기록과 참가자 경기장 중계 — 2026-09-20

심판과 관리자가 필드·벤치 배치를 따라가며 선수와 이벤트를 차례로 선택하던 화면을 팀별 전체 명단 중심으로 바꿨다. 선수마다 골·어시스트·경고·퇴장·반칙 버튼과 누적 횟수를 바로 표시한다. 모바일에서는 팀을 전환하고 넓은 화면에서는 양 팀을 나란히 본다. 기존 기록 취소, 두 번째 경고에 따른 퇴장, 경기 종료 확인과 MOM 선택을 유지한다.

참가자는 기존 잔디 경기장, 선수 위치, 점수·시간·기록 배지를 읽기 전용으로 본다. 연습방에 참가자 역할과 중계 링크 복사를 추가하고, 실제 경기에는 `/matches/[id]/watch`와 라이브·경기 상세의 중계 진입 버튼을 추가했다. 참가자 화면은 경기 시계나 기록을 쓰지 않는다. 경기 종료 후 최종 기록을 다시 조회한다.

공유 연습에서는 먼저 접속한 관리자도 심판과 함께 기록할 수 있다. 관리자의 요청은 현재 심판이 검증·적용하고 모든 화면으로 전파한다. 중복 요청을 한 번만 처리하며 다른 관리자와 참가자의 변경 요청은 허용하지 않는다. 경기 시작·시간·종료는 심판이 담당한다. 이는 가상 경기의 임시 역할이며 실제 계정 권한에는 영향을 주지 않는다. 기존에 열린 공유방의 화면은 모두 새로고침해야 새 역할과 명령을 사용할 수 있다.

## 환경과 범위

Supabase 환경 분리와 마이그레이션 이력을 읽기 전용으로 확인했다. 기존 이력 불일치는 남아 있다. 스키마·Auth·Storage·Realtime 설정·마이그레이션·지속 환경변수는 변경하지 않았다. 운영 시뮬레이션 검증은 별도 가상 방의 Broadcast/Presence만 사용한다. 사용자가 열어둔 기존 방과 실제 경기 기록은 조작하지 않는다.

새 DB 참조는 없다. 배포본 참조 150개를 2026-09-15 운영 카탈로그와 대조해 누락 0개를 확인했으며 새 카탈로그 조회는 수행하지 않았다. 기존 Production의 `SUPABASE_DB_URL` 미설정으로 이번 빌드에만 `FAIRGROUND_SKIP_DB_PARITY=1`을 전달했다. 게이트 코드나 지속 환경변수는 변경하지 않았다. 기존 의존성 감사 경고 5건은 남아 있고 의존성은 변경하지 않았다.

검증용 브라우저 공간과 개발 서버를 종료했다. 이번에 생성한 개발 캐시 약 101MB, 배포 복원 폴더와 임시 응답·로그를 정리했다. 기존 사용자 작업과 의존성은 보존했으며 정리 후 프로젝트 용량은 2.4GB다.

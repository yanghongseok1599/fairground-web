# 아이폰 가로 경기장 팝업 회전 수정 — 2026-09-20

아이폰의 세로 뷰포트에서 경기장만 CSS로 가로 회전되고, `document.body`에 포털로 열린 팝업은 세로 방향에 남는 문제를 수정했다. 경기장과 같은 회전 조건을 선수 동작·교체·어시스트·경기 종료 팝업에 전달하고, 회전 시 가용 가로·세로 길이도 바꿔 화면 안에서 스크롤하도록 했다.

`match-dialog-content.tsx`가 회전·크기를 담당한다. 실제 가로 뷰포트에서는 회전을 적용하지 않는다. CSS 회전 상태의 MOM 선택은 `landscape-mom-choices.tsx`의 팝업 내부 목록을 사용해 별도 포털이나 운영체제 선택기가 세로로 뜨지 않도록 했다. 다른 화면의 공통 Dialog/Select 구현은 변경하지 않았다.

## 검증

- 전체 린트 오류 0/기존 경고 18, TypeScript 통과. 기존 경기·MOM·공동 시뮬레이션 테스트 20개, 환경 분리 안전장치 테스트 4개 통과.
- 분리 배포본에서도 대상 린트·타입 검사·관련 테스트 20개 및 Vercel 빌드 통과.
- Chromium에서 390×844, 375×667 세로 뷰포트로 CSS 가로 회전 조건을 재현했다. 선수 동작·교체·어시스트·종료 팝업의 회전이 90도이며 화면 경계 안에 들어오는 것을 DOM 좌표로 확인했다.
- 블루 1번→6번 교체, 블루 2번 득점, 블루 3번 어시스트를 실제 포인터 입력으로 기록했다.
- 회전된 종료 창에서 블루 3번을 MOM으로 선택한 뒤 844×390 실제 가로 뷰포트로 바꿔도 선택이 유지됐다. 실제 가로 상태의 팝업 회전은 `none`이고 기존 Select가 사용됐다. 취소 시 경기는 `live`로 유지됐다.
- 375×667에서 MOM 없음을 명시하고 최종 확인을 눌러 `finished`로 변경했으며 교체·골·어시스트 기록이 유지됐다. 회전된 스크롤 영역은 브라우저의 `scrollIntoView`로 항목을 표시한 뒤 클릭해 확인했다.
- 물리적 아이폰/Safari·안드로이드 기기 테스트는 수행하지 않았다. 스크린샷 캡처 도구가 실패해 새 스크린샷 검수로 기록하지 않는다.
- 배포 후보 HTTP 200, 검색 제외 메타데이터 확인 후 공식 도메인으로 승격했고 도메인 조회 결과가 새 배포 `Ready`와 일치했다.
- 운영 사이트의 별도 연습 경기에서도 회전된 선수·교체·종료 팝업과 MOM 선택 15개를 확인했다. MOM 없음 선택 후 실제 포인터로 최종 확인을 눌러 `finished`가 되는 동작을 검증했다.

## 배포 범위와 환경

직전 운영 파일 914개를 SHA-1으로 확인해 시스템 임시 폴더에 복원하고 이번 3개 소스만 패치했다. 업로드된 916개 파일의 해시를 모두 검증했다. 변경 범위는 해당 소스와 `tsconfig.tsbuildinfo`이며 [배포 명세](2026-09-20-iphone-landscape-dialogs-manifest.json)에 기록했다. 별도 사용자 작업·브랜치의 다른 기능은 배포하지 않았다.

Supabase 환경과 마이그레이션 이력을 읽기 전용으로 확인했다. 기존 이력 불일치는 남아 있고 DB·Auth·Storage·Realtime·마이그레이션·지속 환경변수는 변경하지 않았다. 사용자 공동 테스트방을 조작하지 않고 별도의 탭 전용 연습 경기에서 검증했다.

새 DB 참조는 없다. 배포본 참조 150개를 2026-09-15 운영 카탈로그와 비교해 누락 0개를 확인했으며 카탈로그를 새로 조회하지 않았다. 기존 Production의 `SUPABASE_DB_URL` 미설정으로 이번 빌드에만 `FAIRGROUND_SKIP_DB_PARITY=1`을 전달했다. 게이트 코드와 지속 환경변수는 그대로다. 기존 의존성 감사 경고 5건은 남아 있고 의존성은 변경하지 않았다.

개발 서버와 검증용 브라우저 공간을 종료했다. 이번에 생성한 빌드 캐시 약 99MB, 소스 복원 폴더·임시 응답·로그를 정리했다. 기존 사용자 작업과 의존성은 보존했으며 정리 후 프로젝트 용량은 2.4GB다.

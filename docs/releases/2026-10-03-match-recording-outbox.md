# 현장 경기 기록 기기 저장·재동기화

경기 운영 화면은 IndexedDB 트랜잭션 완료 후 입력 성공을 표시한다. 시작·시간·일시정지·재개·골·도움·카드·취소·교체·MOM·종료·몰수패를 계정별 경기 대기열에 보관하고, 앱이 열려 있는 동안 연결 복구/주기적 재시도로 입력 순서대로 전송한다. 종료는 앞선 이벤트 뒤에서 처리한다.

서버 RPC `apply_match_recording_operation`은 기록 UUID와 사용자·경기·종류·입력을 검증하고, 기존 경기 RPC 실행과 처리 영수증을 같은 트랜잭션에 저장한다. 응답 유실 후 동일 ID 재전송은 재집계하지 않는다. 권한/경기 상태 충돌은 대기열을 보관한 채 자동 전송을 중지한다. 다른 계정으로 전송하지 않는다. 브라우저 탭 간 잠금으로 같은 기기의 중복 기록 화면과 동시 전송을 조정한다.

상단과 전체화면에 `이 기기에 저장됨 · 서버 전송 대기 N건`, `동기화 완료 · 서버 저장 확인`을 구분해 표시한다. 기기 저장 실패는 성공으로 표시하지 않는다. `기록 백업`은 같은 계정의 준비된 경기, 명단, 명령 이력을 JSON으로 내려받는다. 서버에 승인된 명령도 기기 이력에 남긴다.

## 현장 사용 범위

1. 인터넷이 연결된 상태에서 사용할 브라우저/계정으로 경기 운영 화면을 열고 양 팀 명단과 저장 상태를 확인한다.
2. 해당 브라우저에서 입력한다. 서버 장애 시 기기 저장 후 대기 건수를 표시한다.
3. 창을 유지하면 연결 복구 시 자동 전송한다. 창을 닫았으면 같은 브라우저·사이트·계정으로 다시 열어 전송한다. 대기 0건과 동기화 완료를 확인한 뒤 종료한다.
4. 경기마다 담당 기록자는 한 명으로 정한다. 별도 기기에서 서로 다른 UUID로 입력한 골은 별개의 실제 입력이므로 자동으로 합치지 않는다.

이미 방문해 준비한 경기의 HTML 셸과 정적 자산만 SW에 저장해 오프라인 새로고침에 사용한다. 서버 응답은 정상 연결 시 항상 새로 받으며, Supabase 데이터나 POST를 SW에서 캐시/재전송하지 않는다. 대기열은 앱 저장소가 관리한다. 처음 여는 경기/최초 로그인은 연결이 필요하다. 브라우저 데이터 삭제, 시크릿 창 종료, 기기 고장은 로컬 보관 범위를 벗어나므로 현장에서는 일반 창을 유지하고 백업을 내려받을 수 있다.

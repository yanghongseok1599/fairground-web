# 2026-10-03 경기 준비 자동 알림 중지

사용자의 “알림중지해줘” 지시에 따라 다음 팀의 경기 시작 안내·종료 5분 전 재안내와 다다음 팀의 구장 대기 안내를 모두 중지했다. 개발 12:19:25 KST, 운영 12:19:44 KST에 같은 운영 SQL을 적용했다. 명시적인 재개 지시가 있을 때까지 중지 상태를 유지하며, 웹 재배포를 알림 재개 허가로 해석하지 않는다.

## 적용 범위

추적 명령은 `supabase/operations/pause-match-ready-notifications.sql`이며 SHA-256은 `100008892b2406f6c7f857d6bd6c30ca54eb781675aab9b2e13396cd8d777b23`이다. 신규 객체나 마이그레이션을 추가하지 않고 DB 소유자 세션의 단일 트랜잭션으로 다음 경로를 중지했다.

- 전용 예약 작업 `fairground-next-match-ready`, `fairground-next-match-ready-history`의 `active`를 `false`로 변경했다.
- `public.matches`의 `next_match_ready_after_clock` 트리거를 비활성화했다.
- 구형 웹의 호환 호출이 우회 발송하지 못하도록 `notify_next_match_ready(uuid)`의 `authenticated` 실행 권한을 철회했다. `PUBLIC`·`anon`·`service_role`의 기존 실행 차단과 내부 발송 함수 권한은 유지했다.

기존 함수 본문·API 서명·경기 기록 RPC·다른 일반 알림의 `trg_push_dispatch`·RLS·회원 권한은 보존했다. 현재 경기·점수·이벤트·실제 기록 대기열 `fairground-match-recording-v1` 및 기존 알림·회원 푸시 구독을 수정하거나 삭제하지 않았다. 이미 생성·전달된 알림의 회수 작업은 하지 않았다.

## 백업과 검증

개발 스키마 아카이브 564,956바이트, 운영 스키마 아카이브 614,280바이트를 새로 확보하고 `pg_restore`의 목록 검사를 통과했다. 개발에서 정확히 같은 SQL의 트랜잭션 내 중지 상태·정의/권한 diff를 확인한 뒤 전체 롤백으로 원래 상태 복원을 검증했다. 이 검증을 통과한 같은 SQL을 개발·운영에 각각 적용하고 최종 상태를 확인했다.

공개 스키마 diff는 트리거의 활성 상태(정의와 상태 조회의 두 표현) 및 호환 함수 ACL에 한정됐다. 전용 예약 작업 두 개의 비활성화는 별도 상태 조회로 확인했다. 기존 경기·알림의 값과 전체 마이그레이션 이력은 보존됐으며 이력은 개발 20건·운영 82건으로 그대로다. 운영 경기 12개를 보존했다.

12:20:17 KST 운영 재확인에서 전용 예약 작업 두 개는 비활성, 대상 트리거는 `D`, 일반 API 역할의 호환·내부 발송 함수 실행 권한은 모두 차단 상태였다. 경기 준비 알림은 기존 411건·마지막 생성 12:13:26 KST로 유지됐고, 조회 당시 대기 중 HTTP 요청은 0건이었다. 검수를 위한 실제 경기 변경이나 추가 알림 발송은 하지 않았다.

안전장치 4개와 보안 회귀 7개 테스트를 통과했다. 현재 의존성 감사는 기존 빌드 도구 경로의 high 9건으로 [보안 기준선](../security-baseline.md)과 같으며 의존성 변경은 없다.

프런트엔드 런타임 변경이나 운영 웹 승격 없이 DB의 발송 경로를 중지했다. 이번 추적 소스 커밋과 자동 Preview URL·최종 상태는 작업폴더의 제한 권한 기록 `output/ops/2026-10-03-pause-match-ready/web-release.json`에서 확인한다. DB 백업·적용/롤백 영수증·diff·최종 상태는 같은 디렉터리의 환경별 기록에 보관한다.

## 재개 절차

사용자가 명시적으로 재개를 지시한 뒤에만 해당 환경의 제한 권한 `rollback.sql`을 검토하고 단일 트랜잭션으로 예약 작업·트리거·호환 함수의 직전 권한을 복원한다. 복원 후 발송 경로와 대상·중복 방지를 다시 검증한다. 기존 발송 기록·회원 구독을 삭제하거나 실제 경기 대기열을 정리하지 않는다. 앞선 다음 팀/다다음 팀 활성화 문서와 SQL은 과거 반영 기록이며 이번 중지 상태를 자동으로 덮어쓰는 근거가 아니다.

전체 마이그레이션 이력 불일치는 남아 있으며 linked `db push`/`reset`/`migration repair` 금지는 유지한다.

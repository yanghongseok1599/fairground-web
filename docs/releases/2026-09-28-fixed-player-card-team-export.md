# 선수카드 고정 배치 및 팀별 브론즈 PNG

## 변경

- `PlayerCard`는 모든 표시 크기를 850px 기준 캔버스에서 균일 축소한다. 오버롤의 세로 위치는 사용자가 확정한 15%이며, 포지션·팀 로고·국기·이름·배지·기록 좌표도 공통 프레임을 사용한다.
- 홈페이지와 PNG는 같은 React 카드와 고정 캡처 프레임을 사용한다. 투명 PNG는 2160×2700이며 FAIRGROUND 로고는 검정이다.
- 일괄 내보내기는 카드 외형만 브론즈로 지정한다. 실제 오버롤·기록·사진·DB 값과 홈페이지의 원래 카드 등급 선택은 바꾸지 않는다.
- 팀 로고 처리와 이미지 로딩이 완료된 뒤 순차 렌더링하고, 파일마다 PNG 규격과 실패 여부를 기록한다.
- Ego 실행 설정은 셸 환경변수 대신 명시적인 `globalThis.fairgroundExportConfig`로 전달한다. 운영 데이터와 생성 이미지는 Git에 포함하지 않는다.

## 실제 내보내기 검수

사용자의 최종 요청에 따라 ROOT FC A·B팀과 데카트론 관심점·사랑점을 제외했다. 팀 미소속 계정도 팀별 결과에서 제외했다.

| 팀 | PNG | 등록 사진 없음 |
|---|---:|---:|
| FC 수박 | 9 | 0 |
| FC LEGACY | 10 | 0 |
| FC흰둥이 | 13 | 6 |
| BOB FS | 3 | 3 |
| 합계 | 35 | 9 |

- 35/35 생성 성공. 사진 미등록자는 홈페이지의 기본 선수 이미지를 사용했다.
- 전 파일 2160×2700 RGBA, 캔버스 외곽 투명, 검정 로고의 불투명 픽셀과 팀별 수량을 검사했다.
- 팀마다 대표 이미지를 육안 검수했다. ZIP은 4개 팀별 파일과 전체 묶음으로 생성하고 CRC를 검사했다.
- 출력은 상위 작업 폴더 `output/player-cards/팀별_브론즈_선수카드_20260928`에, 원본 조회 데이터와 SHA-256 검수 기록은 `output/ops/2026-09-28-player-card-export`에 보관했다.
- 선수 조회는 운영 공개 뷰의 읽기 전용 요청이다. 이미지 생성으로 DB/Auth/Storage를 변경하거나 중단하지 않았다.

# 예정 대진 삭제 — 19차

사용자가 기존 ‘대진 유지’ 선택을 변경하여 “예정 경기도 다지워라”라고 명시했다. 2026-09-28 22:08 KST 운영 FairGround DB에서 두 대회의 예정 경기 24개를 단일 트랜잭션으로 삭제했다. 대회 자체 삭제는 요청하지 않았으므로 대회 정보는 유지했다.

## 범위와 보존

- `2026 1필드`, `2026 정규 리그`: 대진 24개 → 0개.
- 대상은 모두 예정·0:0·0초였고, 연결 이벤트·명단·알림·활동·갤러리 사진은 없었다.
- 선수 120명의 전체 프로필(이름·번호·사진·카드 설정 포함), 팀 8개, 대회 2개, 참가비를 보존했다. `matches`를 제외한 public 전체 및 Auth 사용자·Storage 객체를 합한 29개 테이블의 행 수와 내용 해시가 동일했다.
- 운영 스키마 및 마이그레이션 이력 변경 없음. 서비스 재시작·웹 재배포 없음.

## 안전 검증

1. 운영 대상 확인, 환경 안전 점검 및 읽기 전용 마이그레이션 이력 조회. 기존 이력 불일치는 그대로이며 linked push/reset/repair를 사용하지 않았다.
2. 561,870바이트의 새 스키마 덤프를 격리 PostgreSQL에 복원했다. 운영과 함수·컬럼·권한·RLS·정책·인덱스·트리거 서명이 일치했다. 운영 회원 데이터는 격리 DB에 복사하지 않았다.
3. 합성 데이터 4개 검수 통과: 정확한 대진만 삭제, 변경/진행된 범위 차단, FK 연결 데이터의 연쇄 삭제 차단, 오류 시 롤백 복구. 변경 파일 ESLint 및 diff check 통과. 앱 변경이 없어 웹 빌드는 수행하지 않았다.
4. 확인된 ID와 행 내용·스키마를 다시 대조하고, 삭제 직전 데이터를 권한 600 파일로 백업·fsync했다. 삭제 후 29개 보호 테이블과 스키마/이력을 검증한 뒤에만 커밋했다.
5. 실제 운영 관리자 화면에서 경기 카드 0개, 두 대회 각각 ‘경기가 없습니다’, 테스트 시뮬레이션 메뉴 없음 확인.

초기 읽기 전용 진단에서 `match_lineups`의 단일 `id` 정렬 가정이 실패했다. 이후 JSON 행 기반 정렬로 수정했으며 이 진단 실패에 쓰기는 없었다. 운영 앱 또는 배포 코드에는 이 진단 스크립트를 포함하지 않는다.

## 증거와 복구 자료

비공개 `tmp/incident-20260928/`: `before-fixture-delete.dump`, `fixture-delete-data-backup.json`, `fixture-delete-plan.json`, `fixture-delete-receipt.json`. 데이터 복구는 백업의 24개 `matches` 행만 별도로 검토하여 트랜잭션으로 복원할 수 있다. 전체 DB를 이전 상태로 되돌리는 작업은 하지 않는다.

공유 가능한 결과: 상위 작업 폴더 `output/ops/2026-09-28-fixture-delete/`. 재사용 코드는 `scripts/ops/delete-scheduled-fixtures.mjs`이며 명시적 연결·ID·외부 트랜잭션 없이는 실행되지 않는다. 이번 승인은 이 24개에 한정하며 향후 새 대진을 자동 삭제하는 권한이 아니다.

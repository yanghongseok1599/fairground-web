# 선수카드 사용자 오류 복구 — 2026-09-11

## 상태

확인했던 5개 문제를 작업 소스에서 수정하고 격리 통합 UI 테스트로 재검증했다. **운영 재배포는 하지 않았다.** 실제 운영 회원/DB/Auth/Storage/마이그레이션 변경 없음.

작업 브랜치에는 운영 배포에 포함되지 않은 등록 안전장치가 이미 존재했다. 이를 되돌리지 않고 보완했다. 아래 통과 결과는 수정한 작업 소스 기준이며, 현재 운영 서비스가 수정됐다는 의미가 아니다.

## 변경 책임

- `src/lib/registration/saved-profile.ts`: 저장 결과가 존재하고 본인 ID인지 확인한 뒤 서버 행을 Player로 변환. 저장 0건/다른 계정/오류를 성공 처리하지 않는다.
- `src/stores/authStore.ts`: 생성/수정에 저장 확인 적용. 수정은 id만 확인해 로컬 값을 추측하지 않고 서버가 반환한 사진·이름·배지·통계를 반영. 응답 중 계정이 바뀌면 다른 계정을 덮어쓰거나 완료 처리하지 않는다.
- `src/hooks/useCardBadgeEligibility.ts`, `src/lib/player-card/badge-edit.ts`: 조회 성공/실패와 사용자 편집 의도를 분리. 이름/사진만 수정하면 배지 필드를 보내지 않는다. 조회 실패는 빈 목록으로 변환하지 않고 기존 배지를 유지한다.
- `src/app/my/card-edit/page.tsx`: 기존 선수 ID별 최초 초기화 보호를 유지하고 계정/선수별 폼을 분리. 동일 계정 재조회는 입력을 유지하며 계정 전환은 사진 등 상태를 초기화. 프로필이 아직 없는 동안 빈 폼으로 초안을 덮어쓰지 않는다. 새 배지 편집 메타데이터는 선택 항목이라 이전 초안도 읽을 수 있다.
- `src/components/player-card-photo-error.tsx`: 등록/편집 공통 오류 복구 버튼. 실패한 선택만 취소하고 마지막 유효 사진과 다른 입력은 유지한다.
- `src/lib/player-card/upper-body-portrait.ts`, `src/components/player-card.tsx`: 여자/성별 비공개·미제공 인물에는 그림자를 켜지 않음. 확인된 남성은 기존 그림자 유지. 두 미리보기에는 사용 가능한 성별을 전달. 공개 API에 비공개 성별을 추가하지 않음.
- `src/app/my/badges/page.tsx`: 같은 배지 조회 함수의 오류 반환 계약에 맞게 오류를 잡고 재조회 제공. 처리되지 않은 Promise 오류나 빈 인벤토리 오인을 방지.

## 실제 화면 재검증

수정한 실제 페이지·authStore·dataStore·사진 처리를 브라우저에서 실행했다. 서버 응답/라우팅만 모의했고 실제 파일 선택과 화면의 입력/저장 버튼을 사용했다. 테스트용 가상 선수 사진과 localhost 전용 저장 데이터만 사용.

| 기존 재현 | 수정 후 관찰 |
| --- | --- |
| 저장 0건인데 완료 | 요청 1/저장 0건, '저장이 확인되지 않았습니다' 표시, 완료/이동 없음. 입력 유지 및 새로고침 후 초안 복원 |
| 배지 조회 실패→이름만 저장→배지 유실 | 오류와 재조회 버튼 표시. 이름은 저장되고 first_goal 장착 유지 |
| 배지 재조회 | 실패 후 재조회 성공. 그 뒤 사용자가 직접 해제한 경우에만 빈 장착 목록 저장 |
| 프로필 재조회 중 입력 초기화 | '재조회에도 유지되는 이름' 그대로 유지. 다른 계정으로 바꾸면 '다른 선수'로 초기화되어 섞이지 않음 |
| 여자 카드 그림자 | 카드 인물과 사진 미리보기 computed filter 모두 none |
| 손상 사진으로 저장 잠김 | 실패한 사진 선택 취소→이름/기존 사진 유지→정상 저장→새로고침 유지 |
| 등록 페이지 손상 사진 | 오류 취소 후 사진을 새로 준비하지 않고 이름/번호/포지션 입력→선수 카드 생성 완료 |
| 정상 얼굴 합성·저장 | 실제 파일 선택으로 준타스 상반신 합성, 저장 후 새로고침에서 WebP 사진 로드 성공, 그림자 없음 |

기존 사진의 X는 새 사진 선택 취소 버튼이며 삭제 오류라는 과거 진단은 철회된 상태다. 새 복구 버튼은 이 정상 동작과 별개로 **실패한 선택만** 취소한다.

## 자동 검증

```sh
node --test tests/player-card-edit-recovery.test.mjs tests/player-card-photo-read.test.mjs tests/registration-integrity.test.mjs
npm run test:player-card
npm run test:player-card-head
node --experimental-strip-types tests/player-card-upper-body.test.ts
npm run lint
npx tsc --noEmit
npm run build
```

- 저장/복구 관련 테스트 44개 통과. 0행, 타 계정, 서버 정규화 값, 지연 응답 중 계정 전환, 배지 조회 오류/재시도/의도적 해제, 기존 초안 호환, 사진 읽기 오류/중단/시간 초과 포함.
- 카드 프레임/사진 fallback/준타스 asset/얼굴·머리카락/상반신 하단 정렬/스킨 테스트 통과.
- 린트 오류 0, 기존 경고 18. TypeScript와 프로덕션 빌드 통과.
- 빌드 사전검사에 SUPABASE_DB_URL이 없어 로컬 정책에 따라 DB 조회는 건너뛰었다. 따라서 실제 DB 스키마 검증 통과로 표현하지 않는다. 검사 설정이나 운영 환경변수를 변경하지 않았다.
- Supabase 개발/운영 분리 통과. 원격 마이그레이션 이력 조회만 했고 기존 불일치는 남아 있다.

## 배포 전 남은 검증

1. 실제 테스트 계정의 로그인→두 사진 방식→저장→재로그인 및 DB 값 일치. 현재 격리 서버 결과를 실제 운영 RLS 검증으로 대체하지 않는다.
2. 실제 iPhone Safari의 HEIC/대용량 사진/첫 모델 로딩/네트워크 단절·복귀와 성능. 이번에는 데스크톱 Chromium으로 확인했다.
3. 현재 운영 배포와 작업 브랜치가 다르므로, 검증되지 않은 다른 등록/RPC 변경을 통째로 배포하지 않는다. 이번 수정과 필요한 기존 클라이언트 안전장치만 함께 구성해 배포 전후 재검증한다.

사진 픽셀·준타스 유니폼·상반신 크롭·하단 정렬은 바꾸지 않았다. Lazyweb 오류 안내 사례를 참고해 오류 가까이에 재조회/취소를 제공했고 화면 재설계는 하지 않았다: [참고 기록](https://www.lazyweb.com/agentic-search/12f00885-e8a2-49d1-b41f-418d6a43c61e).

## 사용과 범위

로그인 없이 자동 시뮬레이션 또는 수동 경기 운영을 사용할 수 있다. 자동 진행은 기본 60배속으로 12초 동안 득점·어시스트·반칙·경고·누적 퇴장을 기록하고 2:1로 종료 확인을 기다린다. 운영자가 MOM 또는 MOM 없음을 선택해 종료한다. 새 테스트 경기 버튼으로 0:0부터 다시 시작한다.

기록은 현재 탭의 전용 `sessionStorage` 키에만 보관하며, 새로고침하면 일시정지 상태로 복원한다. 실제 경기·선수·순위·알림을 변경하지 않는다. 공식 경기 경로의 `AdminGuard`는 유지했다. 이 기능은 운영 화면 연습용이며 DB 트랜잭션·RLS·여러 기기의 실시간 동기화를 검증하지 않는다.

## 배포 소스와 검증

직전 운영 소스 897개를 파일별 SHA-1으로 검증해 시스템 임시 폴더에 복원한 뒤, 구현 커밋의 14개 파일만 패치했다. 타입 검사에서 생성한 `tsconfig.tsbuildinfo`를 포함해 업로드 소스는 906개이며 검증본과 전부 일치했다. 작업 브랜치 전체와 기존 미완료 작업은 포함하지 않았다. 변경 해시는 [배포 명세](2026-09-20-match-simulation-manifest.json)에 기록했다.

- 신규 시뮬레이션 동작 테스트 9개 및 기존 경기 종료·MOM·전후반·교체·다음 경기 준비 관련 테스트 통과.
- 린트 오류 0/기존 경고 18, TypeScript, 빌드 통과. 분리 배포본도 타입 검사·대상 린트·신규 테스트·Vercel 빌드 통과.
- 로컬 브라우저에서 자동 경기, 수동 교체, MOM 선정과 종료, 새 경기 개설, 새로고침 복원, 390px 모바일 화면을 검증했다. 공식 경기 경로의 비로그인 접근은 로그인으로 이동했다.
- 운영 검증 중 전체화면 경기장이 종료 다이얼로그보다 앞에 표시되는 기존 레이어 문제를 발견했다. 경기장의 레이어를 포털 다이얼로그가 앞에 표시되도록 맞췄으며, 390×844 화면에서 MOM 선택과 종료를 재검증했다. 공통 화면 수정이므로 공식 경기의 전체화면에도 적용된다.
- 도메인 연결 전 새 배포 경로의 HTTP 200과 검색 제외 메타데이터를 확인했다. `vercel promote` 후 공식 도메인이 새 배포를 가리키고 `READY`임을 확인했다.
- 운영 브라우저 자동 진행 결과: 720초, 2:1, 이벤트 10개, 시계·자동 진행 정지. 자동 진행 중 관측한 `fetch` 요청은 0건이었다.
- 최종 운영 배포의 390×844 전체화면에서 블루 3번을 MOM으로 선정하고 종료한 뒤 새 경기를 개설해 0:0 예정 상태로 초기화했다. 이 구간에는 기존 공통 헤더의 인증·알림 조회 등 GET/HEAD 요청이 있었으며 데이터 쓰기 요청은 없었다.

## 환경

DB·Auth·Storage·실제 회원 데이터·마이그레이션은 변경하지 않았다. 기존 Supabase 마이그레이션 이력 불일치는 그대로 남아 있다.

새 DB 참조는 없다. 배포본의 DB 참조 150개를 2026-09-15 운영에서 읽은 기존 카탈로그와 대조해 누락 0개를 확인했다. 이번에 운영 카탈로그 전체를 새로 조회한 것은 아니다. Vercel Production의 기존 `SUPABASE_DB_URL` 미설정 때문에 배포 명령 한 번에만 `--build-env FAIRGROUND_SKIP_DB_PARITY=1`을 전달했다. 지속 환경변수와 게이트 코드는 변경하지 않았다.

검증용 개발 서버를 종료하고 브라우저 TaskSpace, 빌드 캐시, 복원 소스, 임시 스크린샷과 응답을 정리했다. 기존 사용자 변경과 의존성을 보존했으며 최종 프로젝트 용량은 기존과 같은 2.4GB다.

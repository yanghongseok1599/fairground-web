# 2026-10-14 개발 테스트·퀴즈 DB 복구

운영 DB 연결·조회·변경, 웹 배포, 커밋·푸시 없이 개발 환경만 수정했다. 기존 사용자 소스와 미추적 퀴즈·제안서 작업을 포함한 전체 소스를 검증했다. CLI의 운영 연결은 사용하거나 변경하지 않았다.

## 테스트 수정

- 서비스워커 테스트는 현재 v4 캐시 보존과 이전 v2/v3 캐시 삭제를 검사한다.
- 코트 배치 테스트는 분리된 `benchRoster`의 실제 동작으로 선출 제외·플레잉코치 보존을 검사한다.
- 참가비 테스트는 기존 공용 TypeScript 로더로 경로 별칭을 해석하고 실제 상수를 사용한다.
- 승부차기 테스트는 O/X 시도 배열 인수와 시계 정지 후 저장 순서를 검사한다.
- OAuth 테스트는 공용 내부 경로 검사 함수의 기본값과 외부 목적지 차단을 검사한다.
- 전체 DB 검사에서 발견한 과거 fixture도 수정했다. 가입 테스트는 실제 Auth 트리거의 프로필 생성·명시적 동의를 사용한다. 준비 알림은 현재 중지 상태부터 검증하고, 폐기할 로컬 복제 DB에서만 기존 알림 로직을 시험한 뒤 다시 중지한다.
- 프로필 권한 테스트는 익명·일반 회원의 비공개 7열 직접 조회 거부와 본인 RPC 반환을 함께 검사한다. 실패를 숨기기 위해 애플리케이션 동작이나 보호 조건을 약화하지 않았다.

## 개발 DB 적용

| SQL 버전 | 적용 내용 |
|---|---|
| `20260911000000` | 퀴즈 테이블·인덱스·RLS와 `get_futsal_quiz_leaderboard`, `register_futsal_quiz_result` 추가 |
| `20261003010000` | 개발에 누락됐던 소유자 전용 사진 바이트 축소 분기 추가 |
| `20261014020000` | 개발의 과도한 프로필 테이블 SELECT 회수, 기존 공개 32열 권한 복원 |

퀴즈 SQL은 적용 전 PUBLIC 테이블 권한 회수와 다차원 배열 검증을 보완했다. 일반 API는 테이블을 직접 읽거나 쓰지 않고 RPC만 호출한다. 서버 채점, 동점 순위, 같은 UUID 재전송, 다른 내용의 재전송 거부와 동시 요청을 검증했다. 이 기능은 반복 참가 가능한 재미용 공개 닉네임 순위이며 회원 인증이나 경품 경쟁을 위한 구조가 아니다.

사진 변경은 기존 동의 검증 함수에 소유자 세션·정확한 원본/결과 해시·사진 외 모든 값 불변·작은 WebP만 허용하는 분기를 추가했다. 실제 사진이나 동의 값을 수정하지 않았다.

프로필은 테이블 단위 SELECT가 기존 컬럼 허용 목록을 우회하고 있었다. PostgreSQL의 테이블 권한 회수 시 사라지는 컬럼 권한을 같은 공개 32열로 명시 복원했다. 비공개 7열(`birth_date`, `email`, `gender`, `has_player_experience`, `phone`, `portrait_consent_at`, `team_role`)의 직접 접근을 막고, 본인·관리자 RPC와 기존 공개 뷰의 접근 계약은 유지했다. 새 권한 SQL은 개발 대상 마커 없이는 중단한다.

첫 개발 스키마 백업 602,876바이트를 PG17에 복원해 정의·소유자·권한 1,726개를 정확히 대조했다. 퀴즈는 객체 16개만 추가했고 기존 공개 테이블 35개와 이력 26건을 보존했다. 후속 백업 610,000바이트·1,742개 정의를 다시 복원한 뒤 함수 1개와 테이블 ACL 1개만 달라지는 것을 확인했다. 각 변경의 적용·롤백과 역할 검사를 통과했다.

적용 후 기존 공개 테이블 36개의 행 해시는 유지됐고, 이력은 기존 26건에서 퀴즈 1건·후속 2건만 추가하여 29건이다. 합성 hosted 검수 입력은 savepoint로 롤백해 남기지 않았다. 이전 `_fnsnap_before` RLS 차단과 준비 알림 중지는 유지한다. 전체 마이그레이션 이력을 복구한 것이 아니며 linked push/reset/repair 금지는 그대로다.

## 최종 검증

- 전체 테스트 파일 **148개**: 비DB 121개 파일에서 **669/669**, DB 27개 파일에서 **178/178** Node 테스트 통과. 실패·스킵·취소 0.
- 설문 128개·설문 결과 25개·퀴즈 57개 내부 검사도 통과했다. 해당 파일의 Node 래퍼가 위 집계에 포함되므로 내부 검사 수를 중복 합산하지 않는다.
- DB 테스트는 현재 개발 스키마를 파일마다 복제한 로컬 DB에서 실행했다. 실행기와 재현 방법: [로컬 DB 회귀검증](../../scripts/testing/README.md).
- `npx tsc --noEmit` 통과, `npm run lint` 오류 0·기존 경고 16개.
- 퀴즈와 제안서 등 미추적 소스를 제외하지 않은 정상 `npm run build` 통과. 개발 DB 카탈로그·미디어 검사와 TypeScript·Next 빌드·sitemap을 모두 수행했고 게이트를 우회하지 않았다.
- 개발 대상 실제 SQL 역할 검사 20개 통과. 공개 프로필 조회 200, 비공개 프로필·퀴즈 원본·함수 스냅샷 직접 조회 401/42501. 본인·관리자 RPC는 승인된 범위에서 정상 동작한다.
- 퀴즈 실제 RPC 조회 200, 잘못된 등록 입력 400/22023. 로컬 HTTP 11경로는 10개 200 및 `/standings`의 의도된 307이었다.
- 실제 브라우저에서 퀴즈 10문항·채점·성적표·빈 랭킹 조회, 선수 검색·상세 카드, 팀 카드, 선수 랭킹을 확인했다. 브라우저의 Supabase 리소스는 개발 호스트만 사용했고 닉네임 등록이나 회원 로그인·설문 제출은 하지 않았다.
- 퀴즈 순위 기능은 검증용 빌드 환경에서만 활성화했다. 원본 `.env`와 운영 기능 플래그는 변경하지 않았다.
- `npm run security:audit`는 기존 `braces` 계열 높음 9건으로 실패한다. 앞선 로컬 깊이 보완책은 유지되며 이번 테스트·DB 수정으로 공식 패치가 없는 경고를 숨기지 않았다.

백업·정의 diff·롤백·적용 영수증과 검사 로그는 Git 밖 Codex Security 영구 아티팩트의 `artifacts/2026-10-14-dev-tests/`에 보관한다. 검증 설치물과 임시 DB는 종료 후 정리한다.

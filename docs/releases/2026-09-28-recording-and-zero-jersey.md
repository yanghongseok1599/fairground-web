# 공동 경기 기록 및 0·00 등번호 — 운영 반영 전 검수

운영 DB와 운영 웹은 이번 변경으로 수정하지 않았다. 아래 결과는 로컬 구현과 격리 PostgreSQL 검증 결과이며, 운영 적용 완료나 무장애 보장이 아니다.

## 구현한 동작

- 주심은 득점·반칙·경고·퇴장을 입력한다. 부심은 같은 공동 목록에서 각 득점에 어시스트 선수를 연결하거나 어시스트 없음을 확인한다. 심판의 별도 승인 요청 단계는 없다.
- 관리자는 잘못된 기록을 취소하고 보강하며 MOM과 최종 기록을 확정한다. 취소된 원본과 입력·취소 담당자, 변경 이력을 보존한다. 확정 후의 기록은 잠긴다.
- 득점에 같은 팀의 다른 선수만 어시스트로 연결할 수 있고, 득점당 유효 어시스트는 하나다. 득점 취소는 연결된 어시스트도 취소한다.
- 시계가 멈췄고 모든 득점의 어시스트 확인이 끝났으며 관리자가 확인한 기록 버전이 최신인 경우에만 확정한다. MOM, 개인 통계, 팀 순위와 확정을 같은 트랜잭션에서 처리한다.
- 기록 입력은 전송 전에 해당 계정·경기별로 기기에 보관한다. 요청 ID를 유지해 재전송하므로 서버 저장 후 응답이 유실돼도 같은 요청이 중복 집계되지 않는다. 다른 계정의 요청을 재전송할 수 없다.
- 경기 시계 저장은 시작·재개한 담당 계정만 수행한다. 부심 화면은 시계를 덮어쓰지 않는다.
- `0`, `00`, `1`~`99`를 등록할 수 있다. `00`은 문자열 표기를 유지하며 카드·일반 선수 명단·경기 기록 명단·검색·PNG 파일명에서 `0`과 구분한다. 출전 명단에도 해당 경기 등번호 표기를 저장한다.
- 기존 회원의 미등록 기본값 `number=0`과 본인이 등록한 `0번`을 구분한다. 기존 회원 행을 일괄 변경하거나 동의 완료로 간주하지 않는다.

기록 API·권한 판정·기기 보관·공동 기록 패널은 `src/features/match-review/`, 등번호 변환은 `src/lib/jersey-number.ts`로 분리했다.

## 검증

- 일반 회귀 검사: 298개 통과. 작업 폴더에 먼저 존재하던 퀴즈 검사도 포함하며, 관련 없는 변경은 이번 커밋에서 제외한다.
- 격리 PostgreSQL의 실제 함수·RLS 검사: 26개 통과. 승인된 주심·부심·관리자 계정, 역할 침범, 기존 RPC 및 직접 쓰기 우회, 응답 유실과 재전송, 동시 어시스트, 취소 원본 보존, 오래된 검수 버전, MOM·랭킹·팀 순위, 초상권 동의, 0·00 보관을 검증했다.
- TypeScript 및 Next 빌드 통과. 린트 오류 0개, 기존 경고 16개.
- 실제 운영 스키마의 **스키마 전용 백업**을 로컬 PostgreSQL 17에 복원하고 아래 3개 SQL을 순서대로 적용했다. 실제 회원 데이터는 복사하지 않았다.
- 합성 경기로 PC 역할별 버튼과 최종 확정 차단을 확인했다. Chromium의 390×844 / 844×390 화면에서 시간·점수 고정, 공동 기록 패널 한 개, 가로 넘침 없음, `0`/`00` 표기, 어시스트 팝업을 확인했다. 네이티브 전체화면이 없는 경우도 확인했다.
- 스크린샷 캡처가 시간 초과되어 이미지 기반 외관 검수는 완료로 보지 않는다. 실제 iPhone Safari·Android와 운영 계정 3대의 통합 리허설은 남아 있다. 임시 QA 라우트는 제거했다.

검증 증거와 카탈로그 diff는 프로젝트 상위 `output/ops/2026-09-28-match-workflow/`에 보관한다. 인증 정보와 원본 운영 스키마를 Git에 넣지 않는다.

## 적용할 SQL과 배포 순서

1. `20260928010000_match_finalization_regression_fix.sql`: 기존 종료 집계·MOM·자동 퇴장 취소 보정.
2. `20260928020000_referee_recording_admin_confirmation.sql`: 기록 역할·골 연결·재전송 중복 방지·관리자 확정.
3. `20260928030000_zero_jersey_numbers.sql`: 프로필과 출전 명단의 0·00 표기, 공개 뷰, 동의 검사.

운영 이력 불일치가 남아 있어 `db push`, `migration repair`, linked reset 금지는 유지한다. 운영 변경 전 최신 스키마/이력과 검증한 차이가 같은지 다시 확인하고, 제한된 적용 경로를 확정해야 한다. 운영 중인 경기가 없는 시간에 SQL과 웹을 함께 전환하고 모든 기록 기기에서 새로고침해야 한다. 새 RPC가 없는 DB에 웹만 먼저 배포하면 기록할 수 없다. 이번 로컬 빌드의 `FAIRGROUND_SKIP_DB_PARITY=1`은 컴파일 확인용이며 운영 배포 승인 또는 정합성 확인을 대신하지 않는다.

## 운영 리허설에서 확인할 사항

- 두 심판 기기의 미전송 건수가 모두 0인지 관리자가 직접 대조한다. 다른 기기의 오프라인 입력 유무를 서버가 보장할 수 없다.
- 서버가 거절한 충돌·오입력은 자동 삭제하지 않는다. 해당 기기의 보관 기록과 서버 기록을 관리자가 대조해야 한다. 현 버전에는 거절된 입력의 자동 병합이나 기기 보관 해제 기능이 없다.
- 브라우저 데이터 삭제, 기기 분실, 강제 종료 전 저장 공간 부족까지 복구를 보장하지 않는다. 입력 저장 실패는 성공으로 표시하지 않는다.
- 주심·부심은 빈 역할을 먼저 선택한다. 담당 변경 화면은 아직 없으므로 경기 전에 계정과 배정을 확정한다.
- 기존 스킬 챌린지 전용 집계 RPC의 숫자형 등번호는 이번 변경 대상이 아니다. 일반 선수 카드와 경기 명단의 `00` 지원과 구분한다.
- 새 권한은 기존 직접 이벤트 쓰기·종료 RPC를 막는다. 웹만 구버전으로 되돌리는 방식은 안전한 복구가 아니다. 기록을 삭제하거나 운영 전체 덤프를 덮어쓰지 말고, 검증한 기능 수정으로 복구한다.

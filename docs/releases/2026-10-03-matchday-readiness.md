# 경기 당일 제어·종료 확정 · 2026-10-03

**DB와 웹의 개발·운영 반영을 완료했다.** 경기 종료 확정, 두 계정의 기록 공유, 오프라인 복구를 검수했고 자동 Preview와 운영 배포가 Ready다.

## 운영 정책

심판이 경기 시작·중지·재개·종료를 담당한다. 승인된 관리자는 심판이 조작하지 못했을 때 같은 경기 화면에서 개입한다. 이번 변경으로 회원의 역할이나 비밀번호를 바꾸지 않았다.

경기 중에는 점수·이벤트·진행 상태를 실시간 공유한다. 사용자는 **종료 즉시 확정 반영**을 선택했다. 선수카드의 누적 통계와 경기결과·리그순위는 경기 종료 트랜잭션에서 확정하며, 열려 있는 관련 화면도 확정된 값을 다시 조회해야 한다. 경기 도중 입력한 득점을 누적 시즌 통계에 미리 더하지 않는다.

출전 명단이 있으면 명단의 선수에게 출전과 기록을 집계한다. 명단이 없으면 유효 이벤트의 선수와 MOM을 기준으로 집계하는 기존 정책을 유지했다. 등록된 팀원 전원이 실제로 출전했다고 추정하지 않는다.

## 수정한 DB 동작

`20261003050000_matchday_finalization.sql`은 다음을 반영한다.

- 시간 관리 기기가 아닌 관리자도 중지·종료 시 관측한 마지막 시간과 전후반을 전달할 수 있다. 서버는 제어 버전을 확인한 뒤 저장된 시간보다 줄어들지 않게 같은 트랜잭션에서 반영한다. 이전 기기의 지연 타이머가 이를 덮어쓰지 않는다.
- 다른 기기가 이미 제어를 변경했으면 오래된 중지·재개를 `superseded` 영수증으로 남긴다. 응답 유실 뒤 같은 UUID를 재전송해도 처리 결과가 유지되며 뒤에 쌓인 득점 기록은 계속 전송할 수 있다. 서버 조회의 `supersededOperationIds`는 요청한 기록자의 작업만 반환한다.
- 오래된 종료 요청은 조용히 성공 처리하지 않는다. 이미 종료된 경기에 대한 재전송은 집계를 중복 적용하지 않는다.
- 종료·몰수 종료와 기록 진입 RPC가 경기 행을 잠그기 전에 같은 트랜잭션 잠금을 확보한다. 여러 경기 종료가 서로 다른 팀 행을 잡은 채 전체 순위를 갱신하며 교착하는 상황을 방지한다.
- 기록 조회·진입 RPC는 승인된 심판/관리자 프로필을 명시적으로 검사한다. 일반 권한 헬퍼를 넓히거나 기존 회원 역할·RLS를 해제하지 않았다.

실제 정의 diff는 기존 함수 4개(`apply_match_recording_operation`, `get_match_recording_snapshot`, `end_match`, `forfeit_match`) 교체와 `match_recording_receipts.outcome` 컬럼/제약 추가다. 카탈로그 diff에는 교체 함수와 새 컬럼의 기존 서비스 역할 권한을 포함해 추가 정의 10개·제거 정의 4개가 기록됐다. `anon`·`authenticated`의 영수증 직접 조회/수정 권한은 여전히 없다.

## 현장 사용 시 보존해야 할 경계

연결이 없는 동안 기록은 해당 기기에 보관되며 다른 기기에 즉시 전파할 수 없다. 알려진 다른 기기의 미전송 기록은 경기 종료 전에 동기화를 확인한다. Presence에 나타나지 않는 오프라인 기기의 대기열까지 서버에서 모두 확인할 수는 없으므로, 심판·관리자는 종료 전에 기록자들의 전송 완료를 확인해야 한다. 같은 실제 사건을 두 사람이 별도 UUID로 입력하면 서로 다른 기록이므로 기록 담당을 나눈다.

외부 네트워크와 Supabase의 무장애를 보장하지 않는다. 기록 보존·재전송·중복 방지와 확인된 장애 시나리오를 근거로 보고한다. 실제 경기의 IndexedDB `fairground-match-recording-v1`이나 영수증을 임의 삭제하지 않는다.

백업·적용 영수증·정의 diff·보호 행 해시·테스트 로그는 Git 외부 `output/ops/2026-10-03-matchday-readiness`에 보관한다. DB 자격증명과 전체 비공개 카탈로그는 Git에 넣지 않는다. 전체 마이그레이션 이력 복구는 아니며 linked `db push`·`db reset`·`migration repair` 금지는 유지한다.

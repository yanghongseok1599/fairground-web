# PC 팀 카드 클릭 복구

## 재현 및 원인

공식 `/teams` 페이지에서 마우스로 ROOT FC A팀 카드를 클릭할 때 `pointerdown`은 카드 IMG에 발생했지만, `pointerup`과 `click`은 슬라이더 DIV로 전달됐다. 팀 이동 링크는 생기지 않았다. 같은 버튼을 키보드 Enter로 선택하면 팀 이동 링크가 표시됐다. 팀 상세 주소로 직접 접속하면 선수카드 6개가 조회돼 클릭 처리와 데이터 조회 문제를 구분했다.

공유 `TeamMarquee`가 모든 마우스 누르기에 `setPointerCapture`를 즉시 호출하여 자식 버튼의 클릭 대상을 빼앗았다. 홈페이지 팀 카드도 같은 컴포넌트를 사용한다.

## 수정

- 포인터 누르기에는 시작 위치만 기억하고, 수평 이동이 4px를 넘는 실제 드래그에서만 포인터를 캡처한다.
- 드래그 종료 뒤 클릭 억제를 유지하면서 다음 일반 클릭과 키보드 활성화는 허용한다. 터치 스크롤, 보조 포인터, 오른쪽 클릭은 가로채지 않는다.
- 캡처 전 포인터 이탈 및 캡처 해제를 처리하여 자동 회전이 멈춘 상태로 남지 않게 한다.
- 팀 목록 하단 여백과 이동 링크의 스크롤 여백을 확보하고, 팀 선택 직후 이동 버튼이 화면에 보이도록 스크롤한다. 기존 화면에서는 고정 푸시 안내가 팀 이동 링크 중심을 가로채는 문제도 재현됐다.
- 기존 카드 디자인, 팀 선택 후 이동 버튼, 가입 신청과 선수 정보 조회는 유지한다.

## 검증

- 실제 컴포넌트 핸들러 회귀 테스트와 팀 홈 테스트 6개 통과.
- 브라우저에서 실제 마우스 클릭 → 선택 1회, 90px 드래그 → 선택 횟수 유지, 다음 클릭과 Enter → 선택 3회를 확인했다. 합성 click 이벤트만으로 검증하지 않았다.
- 모바일 터치 입력 재현에서 탭은 선택 1회, 이후 175px 스와이프는 추가 선택 없이 스크롤되는 것을 확인했다.
- TypeScript 검사 통과. 전체 ESLint 오류 0개, 기존 경고 17개. 후속 수정 파일 ESLint 통과(기존 이미지 경고만 존재).
- [Lazyweb MLS 팀·선수 명단 진입 사례](https://www.lazyweb.com/agentic-search/148e113c-946b-4123-9f89-564a6f81d068)를 확인했다. UI 구조 변경 없이 입력 오류만 수정했다.

## 운영 배포

- 기준 배포 `dpl_2ccGH4uMpXLQxX6HjP4AkXRgDGG7`의 파일로 격리 릴리스를 만들고 이번 변경 3개 파일만 덮어썼다. 기존 다른 작업은 포함하지 않았다.
- Next.js 운영 빌드 통과. 업로드 소스 957개를 예상 SHA-1과 비교하여 누락·추가·불일치 0건을 확인했다.
- 최종 배포 `dpl_2gKeZpa31dYWLSG2wZ1B6TjAEaV8` / `https://fairground-pa83muogi-milestones-projects-d52c4dda.vercel.app`를 공식 사이트로 승격했다. `/teams` HTTP 200과 새 배포 ID를 확인했다.
- 일회성 `FAIRGROUND_SKIP_DB_PARITY=1`은 기존 격리 프런트엔드 배포 방식이다. DB 전체 스키마 검증 성공을 뜻하지 않는다. 운영 DB·회원 데이터·팀 소속 변경이나 DB 중단은 없다.

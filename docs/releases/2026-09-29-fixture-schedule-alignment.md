# 2026-09-29 조별 대진·큐시트·경기 일정 일치

관리자 경기 자동 생성은 팀 조합을 중첩 반복해 한 팀을 연속 세 경기에 배치했고, 큐시트는 별도의 회전 대진을 사용했다. 생성 시각을 `scheduled_at`에 넣어 10월 3일 대회의 모든 경기가 9월 29일로 저장되어 있었다. 조 편성 화면은 `A`와 `A조`를 다르게 처리하고 팀 조회 순서로 시드를 다시 나열했다.

## 구현

- `fixture-timetable.ts`: 큐시트와 실제 경기 생성에서 함께 사용하는 회전 대진·시간표. 한국 시간의 대회 날짜, 12분 경기·8분 전환, 점심 구간, 홀수 팀 부전승을 처리한다.
- 자동 생성은 최신 저장 조 편성·시드를 우선하고, 기존 경기가 있으면 재편성/덮어쓰기를 차단한다. 경기 저장은 단일 INSERT로 처리해 중간 실패로 일부 경기만 남는 것을 방지한다.
- 조 이름 정규화와 시드 순서 보존을 분리했다. 기존 조 ID·순위표를 보존한다.
- 경기 관리에는 실제 날짜·시각·조·경기 번호를 표시하고 시각 순으로 정렬한다. 공개 대회 일정도 같은 비교 함수를 쓴다.
- 경기 생성 전에는 큐시트 미리보기의 시간 설정을 생성 화면으로 전달한다. 생성 후에는 저장된 경기를 큐시트에 표시하므로 새로고침해도 임의의 기본값으로 시간이 바뀌지 않는다. 잘못된 날짜와 조회 실패를 구별해 표시한다.
- 수동 경기 추가도 대회 날짜와 입력한 한국 시간을 사용한다.

## 운영 데이터 수정

대상: `2026 1필드` (`5ff73034-1747-4b9e-874a-6fe19fa68ac1`), 2026-10-03. 사용자가 지정한 시드:

| 시드 | A조 | B조 |
| --- | --- | --- |
| 1 | ROOT FC B팀 | 데카트론 사랑점 |
| 2 | FC LEGACY | BOB FS |
| 3 | 데카트론 관심점 | ROOT FC A팀 |
| 4 | FC 수박 | FC흰둥이 |

별도 시작 시각이 지정되지 않아 기존 큐시트 기본값(10:00, 조별 별도 구장, 20분 간격)을 명시하고 적용했다. 두 조의 순서는 기존 큐시트 회전 방식인 `4–3, 1–2, 4–2, 3–1, 4–1, 2–3`; 각각 10:00, 10:20, 10:40, 11:00, 11:20, 11:40에 시작한다.

12경기는 모두 예정·0:0·타이머 미진행이며 연결된 명단·이벤트·사진·알림이 0건인 것을 확인했다. 기존 경기 ID와 상대 팀 조합, 생성 시각, 상태·점수 등은 보존하고 순번·예정 시각·홈/어웨이 방향과 대상 대회의 시드 순서만 바꿨다. 다른 대회와 대진 공개 상태는 유지했다.

운영 public/auth/storage/마이그레이션 스키마를 새로 백업하고 격리 PostgreSQL 17에 복원했다. 스키마 정의 1:1 대조 후 합성 8팀·12경기로 동일 수정, 다른 테이블 불변, 롤백, 변경된 경기 거부를 검증했다. 운영 트랜잭션은 백업의 전체 경기·대회 행 일치, 상태, 연결 기록, 스키마·이력 일치를 검사한 뒤 진행했다. 운영 스키마 변경과 마이그레이션 추가는 없다(기존 68건 유지).

보호된 로컬 증거: `tmp/fixture-order-repair/`의 `schema-before.dump`, `before.json`, `plan.json`, `expected-after.json`, `receipt.json`, `rehearsal.json`, `rollback-plan.json`. DB 커밋 후 검증용 SELECT에서 트랜잭션 지역 역할이 해제되어 권한 오류가 났고, 쓰기를 재시도하지 않고 새 읽기 전용 트랜잭션으로 12경기·대회 전체 행의 적용 완료를 재확인했다.

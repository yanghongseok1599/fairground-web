# 2026-10-08 설문 전송 정보 보존

사용자의 “지금부터 설문정보 안놓치게 잘 저장해라” 요청에 따라 제출 대기 응답의 브라우저 복구를 보완했다. 서버가 저장 성공을 확인하기 전에는 제출 완료로 표시하지 않는다.

## 저장과 복구

- 완성된 제출 패킷을 UUID별 localStorage 키에 먼저 저장하고 읽어 다시 확인한다. 실패·시간 초과 뒤에도 같은 번호와 답변으로 재전송한다.
- 탭을 닫고 새 탭으로 설문을 다시 열면 가장 오래된 미확인 응답을 복구한다. 재전송 버튼으로 접수를 확인한다. 여러 패킷이 있으면 한 건 접수 후 다음 응답을 보여준다.
- 성공 영수증을 받은 해당 패킷만 제거한다. 다른 대기 응답·다른 기능의 브라우저 저장값·손상된 기록을 일괄 삭제하지 않는다.
- 브라우저 임시 기록 제거가 실패해도 현재 탭의 서버 확인 번호를 보존해 이미 접수된 응답을 다시 미확인으로 표시하지 않는다. 확인 번호는 탭 안에만 남긴다.
- 다른 탭의 미확인 응답이 현재 탭의 작성 중 초안을 덮어쓰지 않는다. 현재 응답의 접수가 끝난 뒤 다른 대기 응답을 복구한다.
- 작성 중 초안과 제출 완료 표시는 기존처럼 탭의 sessionStorage에 보관한다. 입력 이벤트에서 즉시 기록하며, 기기 전체에 완료 표시를 남겨 다른 참가자의 제출을 막지 않는다.
- 브라우저 저장이 차단되거나 용량을 초과하면 탭 닫기·새로고침 시 복구가 제한됨을 안내한다. 브라우저 데이터 삭제나 외부 서비스 장애에 대한 무손실 보장을 뜻하지 않는다.
- 네 개 장문 응답을 각각 3,000자까지 입력했을 때 JSON 이스케이프로 요청이 커져도 수신할 수 있도록 스트림 한도를 96KiB로 조정했다. 문항별 제한과 서버 검증은 유지한다.

## 유지보수 범위

`src/features/festival-survey/draft-storage.ts`는 탭 초안과 영수증, `pending-storage.ts`는 미확인 제출 패킷, `use-survey.ts`는 복구·전송·접수 상태를 담당한다. API와 저장 모듈·훅 생명주기 테스트로 재전송 및 보존을 검수한다.

운영 설문 원문을 수정·삭제하거나 개발 환경에 복사하지 않는다. DB 스키마·마이그레이션·실제 응답 변경은 없다. 운영 읽기 전용 감사에서 UUID PK·RLS·제출/관리자 조회 권한과 직전 카탈로그가 일치했다. 운영 SQL 이력은 87건으로 보존했다.

검수·정상 개발/운영 카탈로그 대조 빌드·배포 증거는 저장소 밖 `output/ops/2026-10-08-festival-survey-durability/`에 기록한다. 실제 운영 응답을 테스트 자료로 추가하지 않는다.

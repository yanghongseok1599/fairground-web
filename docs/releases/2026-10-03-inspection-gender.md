# 선수검인 성별 입력 · 2026-10-03

관리자가 `/admin/inspections`의 선수 이름·팀·생년월일 옆에서 성별을 입력하거나 수정할 수 있다. 선택지는 가입 양식과 동일하게 남성·여성·기타·응답 안 함이다. 저장 전 취소할 수 있고, 명단 자동 갱신 중에도 선택 초안이 유지된다. 저장 후 기존 개인정보 없는 변경 신호와 5초 재조회를 사용한다.

`gender.ts`, `gender-api.ts`, `components/gender-editor.tsx`로 책임을 분리했다. 성별은 기존 관리자 전용 `get_admin_profiles`에서 해당 명단의 `id,gender`만 100명 단위로 조회한다. 사진 데이터는 추가 조회하지 않는다. 검인 전담 권한을 일반 관리자 권한으로 확대하지 않는다.

저장 직전 참가팀·기존 성별을 다시 확인하고 `profiles`의 해당 선수 성별만 갱신한다. 서버 RLS와 변경 행 ID 확인을 유지한다. 기존 생년월일 방식처럼 사전 조회와 갱신은 원자적 비교·교환이 아니므로 거의 동시에 저장하면 마지막 저장이 남을 수 있다. 이를 해결하려고 운영의 비공개 성별 SELECT 권한을 확대하지 않았다.

## 검증

- 입력값·명단 범위·오래된 초안·실패 응답·변경 신호 등 관련 테스트 20건 통과.
- 운영 스키마를 복원한 격리 로컬 DB에서 가상 관리자의 성별 저장/본인 조회, 일반 선수·검인 전담자의 타인 수정 차단 2건 통과. 합성 데이터는 롤백하고 로컬 DB는 정리했다.
- TypeScript와 변경 파일 lint 통과. Supabase 안전 테스트 4건 통과.
- 실제 개발·운영에서 기존 성별 컬럼과 관리자 RPC 정의/권한 확인. 개발·운영 카탈로그와 배포 소스 대조: 타입 컬럼 365개, 조회 87개 통과.
- 기존 DB 구조·권한·회원 정보·환경변수는 변경하지 않았다. 전체 마이그레이션 이력 복구와 별개이며 linked push/reset/repair 금지는 유지한다.

최신 공동 경기 기록 및 순위별 카드 변경을 포함한 커밋 `885f90a`를 기준으로 격리된 배포 소스를 만들고 이 기능만 추가했다. 다른 미완성 변경은 포함하지 않는다. 빌드·운영 배포·자동 Preview 및 브라우저 검수 결과는 Git 외부 `output/ops/2026-10-03-inspection-gender`에 보관한다.

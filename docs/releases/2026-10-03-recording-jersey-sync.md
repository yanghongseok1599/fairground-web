# 경기 기록 화면 등번호 갱신 · 2026-10-03

프로필의 등번호를 수정한 뒤에도 관리자·심판 경기 화면은 IndexedDB에 처음 저장한 `RecordingRoom.players`를 계속 사용했다. 서버 경기 스냅샷은 갱신되지만 선수 명단과 화면의 최초 로컬 상태는 바뀌지 않아 이전 번호가 표시됐다.

공개 경기 선수 뷰에서 해당 두 팀의 ID·팀·등번호·등번호 표기만 약 15~19초 간격으로 다시 조회한다. 기존 명단과 ID·소속이 같은 선수의 등번호 두 필드만 갱신하고, 기록 어댑터가 최신 명단을 화면에 전달한다. 이름·사진·통계·팀 소속·출전 명단·서버 경기 상태·미전송 명령·기록 이력은 덮어쓰지 않는다. 실패하거나 오프라인이면 기존 번호와 기록을 유지하며 화면 소유권이 해제된 응답은 폐기한다.

네트워크 응답 중 새로 입력된 기록을 보존하도록 IndexedDB 트랜잭션 안의 최신 방을 대상으로 병합한다. 단순 새로고침이나 저장소 초기화를 해결책으로 사용하지 않는다. 기존에 열려 있는 구버전 화면은 자동 강제 갱신하지 않으며, 경기 종료 후 운영자가 새 버전으로 다시 진입하면 기기 저장 명단이 갱신된다.

검증: 번호 변경·00 표기·팀 이동 무시·부분 조회·오프라인·중복 조회·늦은 응답 취소·조회 도중 기록 입력 보존 및 실제 어댑터/화면 훅의 번호 반영 테스트. 기존 초기 진입/탭 잠금·기록 취소·기기 저장·재전송·종료 복구 검증도 통과했다. TypeScript 통과, 전체 lint 오류 0건(기존 경고 16건). 개발 실제 카탈로그 대조는 타입 계약 366개·조회 100개 통과.

DB 스키마·권한·회원 데이터·경기 결과는 변경하지 않는다. 배포 빌드/운영 카탈로그 검사와 자동 Preview·운영 배포 결과는 Git 외부 `output/ops/2026-10-03-recording-jersey-sync`에 보관한다. 진행 중인 경기 화면·대기열은 조작하지 않는다.

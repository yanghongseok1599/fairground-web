# 개발 Preview PNG 캡처 및 무인 회귀 검증

## 범위와 원인

- 대상은 `feat/site-essentials`의 개발 Preview다. 기준 커밋은 `c527a90881494b063dd3a3378d110cdcbaace96e`다.
- Ego 0.5.1.13에서 빈 페이지도 `Page.captureScreenshot`이 시간 초과됐다. wrapper의 DPR 보정 후 뷰포트가 반감됐고, clip 없는 CDP 캡처·포커스/창 활성화도 해결하지 못했다. FairGround 화면에만 발생하는 문제는 아니며, Ego 내부 렌더링 원인은 확정하지 않았다.
- 사용자가 승인한 별도 Chromium에서 기존 회귀 시나리오와 실제 PNG 캡처를 실행한다. 사용자 브라우저의 프로필·확장 상태는 변경하지 않는다. Ego 자체를 수정하거나 업그레이드한 것은 아니다.

## 변경

- `--engine chromium`은 고정 버전 Playwright의 headless Chromium과 시스템 임시 프로필을 사용하고, 종료 성공까지 증거로 남긴다. 기본 Ego 경로는 유지한다.
- Vercel GET 메타데이터에서 프로젝트·Preview·READY·정확한 URL·전체 SHA를 확인한 뒤 실행한다. 기존 자동화 인증 값은 표준 입력과 해당 Preview 호스트의 보호 쿠키로만 사용한다. 보호 설정이나 인증 값은 생성·변경하지 않는다.
- CDP 요청 단계에서 각 리다이렉트 경유지를 검사한다. 해당 Preview, 개발 Supabase, 제한된 읽기 전용 정적 파일만 허용한다. 다른 호스트·팝업·검사 오류는 실패다. 선택적인 Vercel 피드백 스크립트는 차단하고 별도로 기록한다.
- PNG는 실제 디코딩·zlib/CRC·크기·빈 이미지·캡처 전후 뷰포트를 검사한다. 실패 시 TXT로 대체하거나 성공 처리하지 않는다. 완성된 팀 카드가 표시된 뒤 캡처한다.
- 공통 시나리오, Chromium 어댑터, 요청 경계, PNG 검증, 실행 제한을 별도 모듈로 나눴다. 제품 소스·DB 스키마·회원 권한은 변경하지 않았다.

## 배포 전 검증

- 비DB 테스트 132개 파일, 858/858 통과. 브라우저 회귀 모듈 테스트는 171개다.
- lint 경고/오류 0, TypeScript 통과, 의존성 취약점 0, 보안 테스트 7/7 통과.
- Supabase 안전 검사와 정상 `npm run build` 통과. 개발 DB의 읽기 전용 카탈로그에서 함수 48개·관계 28개·버킷 1개 및 타입 컬럼 370개·조회 컬럼 103개를 대조했다. 정합성 게이트를 우회하지 않았다.
- 이번 변경은 자동화 전용이며 DB 쓰기 통합 테스트 29개 파일은 다시 실행하지 않았다. 개발 DB 스키마·데이터 마이그레이션은 없다.
- 기준 Preview `https://fairground-nmxyy3lxk-milestones-projects-d52c4dda.vercel.app`에서 최종 후보 무인 회귀 8/8과 PNG 2개(1512×828)를 통과하고 직접 이미지 내용을 확인했다.
- 자동 이동 카드 클릭 1회, 포커스 후 클릭 3회, 이름·로고 수정 취소 3회, 새로고침 후 원본 보존 1회를 검사했다. 취소 구간의 앱 데이터 쓰기는 0건이며 로그아웃·브라우저 종료가 확인됐다.

## 배포 후 확인 및 증거

이 변경만 feature 브랜치에 푸시한 뒤 새 immutable Preview의 전체 SHA·READY·빌드 로그를 확인하고 같은 무인 회귀와 PNG 검수를 다시 수행한다. 최종 배포 URL·커밋·사례별 결과·PNG 해시·종료 영수증은 별도 영구 검증 보고서 `artifacts/2026-10-16-png-capture/report.md`에 기록한다. 저장소 밖에 증거를 보관해 캡처·브라우저 프로필·빌드 캐시가 소스에 섞이지 않게 한다.

서비스 워커는 요청 경계 유지를 위해 차단하므로 PWA·오프라인 동작은 이번 회귀 범위에 포함하지 않는다. 기존 보호 설정을 유지하며 운영 DB·배포·도메인·환경변수는 변경하지 않는다. 운영 연결 가능성이 있는 전역 GitHub DB 검사 워크플로는 `[skip actions]`로 실행하지 않고, 개발 대상 로컬 검사와 Vercel의 정상 빌드 게이트로 검증한다.

## 배포 후 요청 수명 경합 보완

첫 커밋 `0468a875a1f5b3f9fe11f1c044e3fecd94fd7f97`의 자동 Preview는 정상 빌드됐다. 첫 무인 실행은 기능 8개·PNG 2개 이후 요청 감시기 오류로 전체 실패했다. 비밀을 제외한 진단을 추가해 `Fetch.continueRequest`의 사라진 요청 ID 오류를 확인했다. 상세 분류를 추가한 뒤 기본 실행 2회와 10회 반복 실행(22개 사례)은 성공해 간헐적 상태임을 확인했다.

별도 로컬 합성 페이지에서 실제 동일 Chromium 156.0.8078.4의 fetch/XHR 취소·페이지 이동 12/12건이 정확히 `Invalid InterceptionId.`를 반환했고, 미취소 대조군 4/4건은 성공했다. 외부 요청은 0건이다. [해당 Chromium 버전의 FindJob 구현](https://chromium.googlesource.com/chromium/src/+/156.0.8078.4/content/browser/devtools/devtools_url_loader_interceptor.h#251)도 이 응답이 interception job 부재를 뜻함을 확인한다. 합성 재현에는 networkId가 존재했으므로 실제 앱의 ID 미제공 원인까지 같다고 단정하지 않는다.

이미 허용된 목적지의 요청 단계·최초 Fetch ID에서 정확한 `Invalid InterceptionId.`가 발생한 경우만 종료된 interception으로 별도 기록한다. 취소라고 추정하거나 요청을 재시도하지 않는다. 금지 목적지·중복 ID·응답 단계·다른 오류는 여전히 실패하며, 금지 목적지는 차단 명령의 응답과 무관하게 실패를 확정한다. 보완 후 단위·브라우저 검증과 새 커밋의 최종 Preview 결과는 영구 보고서에 추가한다.

보완한 비DB 전체 테스트 867/867, lint·TypeScript·보안 검사 모두 통과했다. 기준 Preview에서 보완한 실행기의 8/8 사례·PNG 2개·로그아웃·브라우저 종료도 통과했다. 최종 검토에서 운영 경계 약화나 입력 재시도는 발견하지 않았다.

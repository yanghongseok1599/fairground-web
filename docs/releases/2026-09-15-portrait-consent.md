# 초상권 동의와 선수카드 이용 제한

## 구현

- 회원가입: 이메일 가입은 기본 미체크 동의 항목을 확인해야 제출된다. Auth 메타데이터의 명시적 `portrait_consent: true`를 프로필 생성 시 서버가 기록한다. 이메일 인증 대기 중에도 DB 기록을 남긴다.
- Google·카카오: 로그인 콜백에서 개인 동의가 없으면 `/my/portrait-consent`로 연결한다. 기존 목적지는 내부 주소만 유지한다.
- 선수카드: 개인 동의가 없으면 생성·수정·내 카드 이미지 저장/공유를 제한한다. 사진이 있다는 이유로 동의 완료로 간주하지 않는다. 기존 개인 동의는 재사용한다.
- 대회 신청: 신청자 개인 동의와 팀 대표의 팀원 동의 확인을 구분한다. 개인 동의 저장 실패 시 신청을 진행하지 않는다.
- 마이페이지: 미동의자는 카드 영역에서 동의하고, 동의자는 최초 동의 시각을 한국 시간으로 확인한다.
- 접속 안내: 로그인한 미동의 회원에게 홈페이지와 공통 화면 상단에서 안내한다. 접속/닫기를 동의로 간주하지 않는다.
- 알림: 개인 동의 상태에서 계산하는 알림함 항목과 카운트 1개를 제공한다. ‘모두 읽음’으로 미완료 동의를 해제하지 않으며, 동의 완료 시 사라진다. 서버 알림의 대량 중복 삽입이나 외부 문자/푸시 발송은 없다.
- 동의 체크는 폼 임시저장에서 복원하지 않는다. 계정 전환 시 입력 화면의 동의 상태를 초기화한다.

## 유지보수

공통 정책·본문·컴포넌트는 `src/features/portrait-consent`에 있다. 기존 `src/components/portrait-consent-card.tsx`는 호환 진입점이다.

`20260915010000_portrait_consent_enforcement.sql`은 기존 OAuth 프로필 생성 함수를 덮어쓰지 않는 추가 트리거이다. 개인 동의 최초 시각을 서버에서 정하고 이후 수정에도 보존하며, 다른 회원이 대신 동의하는 요청과 동의 없는 카드 필드 쓰기를 거부한다. 기존 회원을 자동 동의로 일괄 변경하지 않는다.

화면 구성 참고: [Lazyweb 동의 화면 사례](https://www.lazyweb.com/agentic-search/20ef4d36-e44f-4dfd-8a75-2d39adb6227e).

## 검증

- `npx tsc --noEmit`: 통과.
- `npm run lint`: 오류 0, 기존 경고 18개.
- `npm run build`: 통과. 로컬 prebuild의 DB parity 조회는 `SUPABASE_DB_URL` 미설정으로 생략되었으므로 운영 DB 정합성 검증을 의미하지 않는다.
- 동의 정책/실제 store와 관련 등록·사진 저장 회귀 테스트 45개 및 회원가입 실명 회귀 테스트 5개: 통과.
- 격리된 로컬 PostgreSQL에서 새 마이그레이션 적용 및 DB 테스트 8개: 통과. 최소 스키마 계약을 사용하며 전체 운영 스키마/RLS 재현을 의미하지 않는다.
- Supabase 안전장치 4개 및 기존 보안 테스트 7개: 통과.
- Ego 브라우저 + 로컬 합성 Auth/API + 로컬 PostgreSQL: 가입 체크 기본 해제/버튼 비활성화, 홈페이지 안내, 알림 1개, 카드 편집 직접 진입 차단, 저장 실패 시 체크 유지, 재시도 동의 완료/서버 시각 표시, 알림 0개 및 안내 해제, 기존 동의 회원의 선수카드 실제 저장, 신청자의 기존 동의 표시와 팀원 동의 미체크 시 신청 차단, 모바일 가로 넘침 없음을 확인했다. 실제 회원 데이터는 사용하지 않았다.

```sh
node --test tests/portrait-consent.test.mjs tests/registration-integrity.test.mjs tests/player-card-photo-read.test.mjs
# 로컬의 빈 테스트 DB에만 실행한다.
FAIRGROUND_TEST_DB_URL=postgresql://127.0.0.1:55439/portrait_consent_test node --test tests/portrait-consent-database.test.mjs
```

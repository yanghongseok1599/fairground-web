# 선수 카드 사진 등록 핫픽스 — 2026-09-10

## 변경

- 카드 수정과 선수 등록에 `내 얼굴 등록하기`, `내 유니폼프로필 등록하기`를 분리했다.
- 얼굴 등록은 실제 얼굴 좌표로 준타스 남녀 유니폼에 합성한다. 얼굴이 없거나 여러 명이면 저장하지 않고 오류를 표시한다.
- 유니폼 등록은 팀/역할/성별에 따른 합성을 하지 않고 본인 사진의 배경만 제거한다.
- 잘못 합성된 기존 저장 사진은 원본 재등록이 필요하다. 기존 회원 사진을 일괄 수정하지 않았다.
- UI는 Lazyweb의 [프로필 사진 선택 참고 화면](https://www.lazyweb.com/agentic-search/078f64ad-7b57-427e-84af-1f2ea55a69e5)을 확인한 뒤 두 등록 방식을 명시적으로 나눴다.

## 검증 및 제한

- 린트 오류 0개(기존 경고 19개), TypeScript, 카드 테스트 4종, 보안 회귀 7개, Supabase 안전장치 4개 통과.
- 운영 Vercel 빌드 및 배포 READY 확인. 얼굴 모델, WASM, 준타스 남녀 PNG의 운영 HTTP 200 및 MIME 확인.
- 브라우저에서 얼굴 감지 API가 없는 환경의 합성, 남녀 준타스 합성, 얼굴 없음/복수 얼굴 거부, 근접 얼굴, 모바일 두 버튼 동작 확인. 실물 iPhone Safari와 실제 회원 계정 저장은 검증하지 않았다.
- 기존 의존성 취약점 5건은 남아 있다. 상세는 `docs/security-baseline.md`를 참고한다.

## DB 검사

- Vercel의 `SUPABASE_DB_URL` 미설정으로 첫 배포 빌드는 차단됐으며 운영 별칭은 바뀌지 않았다.
- 운영 프로젝트를 확인하고 관리 API로 카탈로그를 SELECT만 조회했다. 배포용 소스의 함수 35개, 릴레이션 27개, 버킷 1개를 동일한 정합성 검사 함수로 대조해 누락 0개를 확인했다. 기존 동적 릴레이션 호출은 정적 검사 범위 밖이다.
- 이 확인 후 해당 배포 명령에만 `--build-env FAIRGROUND_SKIP_DB_PARITY=1`을 적용했다. 프로젝트의 영구 환경변수나 게이트 코드는 변경하지 않았다.
- 다음 일반 배포 전에는 DB 연결 환경변수와 브랜치의 `register_team` 정합성 문제를 별도로 해결해야 한다. 이 핫픽스 성공을 브랜치 전체의 배포 승인으로 해석하지 않는다.

# 경기 기록 → 랭킹·리그 순위 연동 검수

검수일: 2026-09-20. **판정: 미통과.** 연습 경기의 운영 데이터 분리는 확인했지만, 공식 경기 종료와 징계·MOM 집계에 아래 문제가 남아 있다. 테스트 페이지를 삭제하기 전에 이 문제를 수정하고 재검증할 것을 권장한다.

## 검수 대상과 방법

- 운영 배포: `dpl_G5VCwUz3vYBjsqXErJmryFrdunMU` (`https://fairground-i441r9wck-milestones-projects-d52c4dda.vercel.app`). 배포 소스 933개를 배포 API의 SHA-1과 대조했다. 로컬 작업 브랜치와 배포된 `dataStore.ts`, `mappers.ts`가 달라 최종 실행에는 **배포 원본**을 사용했다.
- 운영 Supabase `ovtnmslyjzvghirdvife`를 읽기 전용으로 조회하고, **스키마만** PostgreSQL 17 임시 로컬 DB에 복원했다. 함수 98개 정의가 모두 동일함을 확인했다. 원본 소유자·권한·RLS·트리거를 유지했다. 실제 회원·팀·경기 행을 복제하지 않았다.
- 합성 회원·팀·시즌·경기를 로컬 DB에 만들었다. 배포된 실제 `dataStore`의 기록/종료 메서드를 SQL 어댑터로 호출했다. RPC는 `authenticated`, 공개 랭킹·순위 조회는 `anon` 역할로 실행했다. 함수 정의나 매퍼를 모킹하지 않았다.
- 브라우저 UI 또는 실제 기기 테스트가 아니라 **운영 코드와 DB 함수의 통합 검수**이다. HTTP/PostgREST와 실시간 알림 전달 자체는 이번 통합 테스트의 범위가 아니다.
- 운영 스키마·데이터·마이그레이션 이력은 변경하지 않았다. 실제 사이트 재배포 및 테스트 페이지 삭제도 하지 않았다. 사용 중인 공유 연습 방은 조작하지 않았다.

## 발견 사항

### P1. 공식 경기 종료가 실패해 랭킹·승점 반영이 완료되지 않음

재현: 공식 경기 시작 → 득점/어시스트/MOM 입력 → 종료. 출전 명단이 있는 0:0 경기에서도 동일하게 실패한다.

오류: `function public.compute_card_rating(bigint, bigint, integer) does not exist`.

`end_match`의 `count(*)` 집계 결과는 `bigint`인데 카드 레이팅 함수는 `integer` 인수만 받는다. 출전 명단 분기와 이벤트만 집계하는 분기 모두 해당한다. 트랜잭션이 롤백되어 경기 종료 상태, 선수 통계, 팀 승점 갱신이 완료되지 않는다.

참고: [종료 함수와 집계](../../supabase/migrations/20260725000000_match_lifecycle_and_finalization.sql), [재현 테스트](../../tests/match-rank-integration.test.mjs).

6개 집계 값을 `integer`로 명시 변환하는 [최소 수정 후보](2026-09-20-end-match-integer-candidate.patch)를 **임시 로컬 DB에만** 적용했다. 이후 승/무승부·득실차·벤치 득점·어시스트·MOM·공개 랭킹·리그 순위 조회·중복 종료 방지·실패 시 롤백이 해당 시나리오에서 통과했다. 이 후보는 아래 두 문제를 해결하지 않으며 배포용 마이그레이션이 아니다.

### P1. 두 번째 경고를 취소해도 자동 퇴장이 남음

재현: 한 선수에게 경고 두 번 → 자동 퇴장 생성 → 경고 한 번 취소. 유효 경고는 1개가 되지만 유효 퇴장이 1개 남는다. 연습 저장소에서는 정상 취소되므로 연습 화면 검증만으로는 공식 경기 오류를 발견할 수 없다.

`cancel_match_event`는 선택한 이벤트만 취소하고, `add_match_event`가 추가한 자동 퇴장과 연결하지 않는다. 종료 집계 오류를 수정하더라도 이 퇴장이 징계 집계에 남을 수 있다. 자동 퇴장의 원인 경고를 명시적으로 연결하고 해당 퇴장만 취소해야 한다. 직접 퇴장을 함께 취소하면 안 된다.

참고: [기록 취소 함수](../../supabase/migrations/20260607000000_match_event_rpc.sql), [자동 퇴장 생성](../../supabase/migrations/20260826000000_auto_ejection_on_second_yellow.sql).

### P2. 출전 명단 없이 MOM만 지정한 선수의 기록 누락

재현: 출전 명단 없이 경기 시작 → 선수 A 득점 → 별도 이벤트가 없는 선수 B를 MOM 지정 → 종료. 위 정수 변환 후보로 종료 오류를 제거한 뒤에도 B의 MOM과 경기 수가 각각 0으로 남는다.

MOM 지정 RPC는 같은 팀 선수를 허용하지만, 종료 함수의 명단 없는 분기는 유효 이벤트에 등장한 선수만 집계한다. MOM 선수를 집계 대상에 포함하거나 명단을 필수로 하는 정책을 일관되게 적용해야 한다.

## 연습 데이터와 실제 순위의 관계

연습 경기는 전용 `createPracticeStore`와 합성 선수를 사용한다. 자동 진행·기록·MOM·종료·재시작에서 실제 Supabase나 운영 저장소 접근 시 즉시 실패하는 기존 테스트로 분리를 확인했다. 공유 방은 Broadcast/Presence로 상태를 전달하며 공식 경기 종료 RPC를 호출하지 않는다. 연습 경기 결과는 실제 개인 랭킹·리그 승점으로 반영되지 않는 설계이다.

검수 시점 운영 `matches` 조회 결과는 0건이었다. 위 결함은 실제 운영 경기 데이터를 만들어 확인한 것이 아니라, 운영과 동일한 정의에 합성 입력을 넣어 재현했다. 과거 경기 결과가 손상되었다고 주장하지 않는다.

## 재현 및 후속 작업

운영 스키마만 복원한 **폐기 가능한 로컬 DB**와 해당 배포 소스를 준비한 뒤 새 테스트 파일을 복사하여 실행한다. 테스트는 합성 행을 생성하므로 평소 개발 DB에서 실행하지 않는다. 호스트 검사로 원격 DB 접속을 거부한다.

```sh
FAIRGROUND_TEST_DB_URL=postgresql://postgres@127.0.0.1:55441/rank_audit \
  node --test tests/match-rank-integration.test.mjs
```

수정 시 기존 마이그레이션을 덮어쓰지 않고 별도 마이그레이션으로 남겨야 한다. 정수 변환, 자동 퇴장의 원인 연결/취소, MOM 집계 대상 보완 후 위 테스트 전체와 직접 퇴장 보존·동시 종료·취소 재시도 회귀를 확인한다. 운영 적용은 저장소의 Supabase 환경/백업/마이그레이션 보호 규칙을 따른다.

정의와 소스 지문, 실행별 결과는 [검수 증거 목록](2026-09-20-match-rank-integration-evidence.json)에 남겼다. 검수 종료 후 임시 DB 서버를 중지하고 DB·배포 소스 복사본·접속 자격이 포함된 임시 CLI 파일을 삭제했다. 기존 작업 파일과 의존성은 보존했다. 종료 시 프로젝트 크기는 2.4GB였다.

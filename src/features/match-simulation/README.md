# 테스트 경기 시뮬레이션

`/match-simulation`에서 테스트 블루·레드, 각 7명(선발 5명/벤치 2명)으로 경기를 연습한다. 관리자 **경기 관리 → 테스트 경기 시뮬레이션**에서도 연다.

## 두 기기로 함께 연습

**함께 테스트할 경기 만들기**를 누르면 고유한 방 링크가 생긴다. 심판 링크와 관리자 링크를 각각 한 명에게 전달한다. `?room=<UUID>`만 있는 같은 링크에서도 각자 역할을 선택할 수 있다.

- 심판: 경기 시작·자동 진행·득점·교체·경고·MOM·종료를 입력한다. 시계는 이 화면에서만 진행한다.
- 관리자: 같은 점수·시간·명단·기록·MOM·종료를 실시간으로 확인하고, 확인 창을 거쳐 두 화면의 경기를 초기화한다.
- 같은 역할의 두 번째 화면은 조작을 잠근다. 심판이 나가거나 연결이 끊기면 진행을 멈추며, 재접속 또는 심판 인계 시 남아 있는 관리자의 최신 기록을 받아 일시정지 상태로 이어간다.
- 접속 중인 브라우저가 상태를 보관한다. 서버에 영구 저장하지 않으므로 모두 탭을 닫고 저장 기록도 사라지면 새 경기로 시작한다. 두 화면을 열어둔 채 사용하는 연습 도구다.
- 방 UUID가 포함된 링크를 가진 사람이 연습 역할에 참여할 수 있다. 역할은 실제 계정 권한 인증이 아니며 운영 DB의 RLS·경기 트랜잭션 검증을 대체하지 않는다.

Supabase Realtime의 별도 `practice-room-v1:<UUID>` Broadcast/Presence 채널만 사용한다. 경기 테이블·RPC·회원 기록·운영 알림에는 쓰지 않는다. 로컬/Preview는 개발 Realtime, Production은 운영 Realtime을 사용한다. 스키마나 환경변수 변경은 필요하지 않다.

## 혼자 연습

- **경기 시작**: 기존 경기 운영 화면으로 득점·어시스트·반칙·경고·퇴장, 교체, 일시정지/재개, MOM과 종료를 직접 연습한다.
- **자동 시뮬레이션**: 60배속으로 12초 동안 샘플 경기를 진행한다. 기본 결과는 2:1이며 경고 2회 누적 퇴장도 포함한다. 수동 기록을 추가하면 결과가 달라진다.
- **진행 속도**: 1/10/60배. 규정 시간에 시계를 멈추고 운영자가 MOM 또는 MOM 없음을 선택해 종료한다.
- **새 테스트 경기**: 확인 후 현재 연습 기록을 비우고 0:0부터 다시 시작한다.
- 같은 탭에서 새로고침하면 `sessionStorage`의 전용 키로 복원하고 시계를 일시정지한다. 다른 기기와 공유하거나 실제 리그에 등록하지 않는다. 저장소가 차단돼도 현재 화면에서 연습할 수 있다.

## 모듈

- `fixtures.ts`: 가상 경기·선수·선발 명단
- `store.ts`: 별도 Zustand 저장소, 시계, 시나리오, 경기 명령
- `persistence.ts`: 탭 전용 저장 및 복원 검증
- `simulation-page.tsx`: 혼자/공유 경기 진입과 탭 보관
- `simulation-workspace.tsx`: 심판 조작 UI와 저장소 주입
- `shared/protocol.ts`: 링크·역할·메시지 계약 및 외부 기록 검증
- `shared/session.ts`: 단일 심판 시계, 접속 좌석, 순서 검증, 재접속 복원, 초기화 승인·중복 방지
- `shared/transport.ts`: Realtime Broadcast/Presence 연결과 정리
- `shared/room-page.tsx`, `shared/admin-view.tsx`: 공유 링크·상태 안내와 관리자 모니터
- `../match-control/`: 공식 경기와 연습 경기가 함께 사용하는 운영 화면·저장소 계약

공식 `/admin/match/[matchId]`는 기존 `AdminGuard`와 운영 저장소를 사용한다. 연습 화면의 Provider 내부만 별도 저장소를 사용하며 전역 `isDemoMode`, 인증 상태, 운영 데이터는 변경하지 않는다. 연습 저장소의 모든 명령은 직접 구현돼 있고 운영 저장소로 돌아가는 경로가 없다. 알림 발송은 0건을 반환한다.

이 도구는 경기 운영 UI와 별도 연습 채널의 여러 기기 동기화를 연습한다. 운영 경기 테이블의 실시간 구독·Supabase 트랜잭션·RLS를 검증하지 않는다.

## 검증

`node --test tests/match-simulation.test.mjs`로 자동 진행·득점 취소·경고 정정·교체·종료 멱등성·잘못된 운영 ID 차단·복원을 검증한다. 기존 경기 테스트, 린트, TypeScript와 빌드도 실행한다.

`node --test tests/match-simulation-room.test.mjs`는 관리자 선입장, 단일 시계, 초기화 재전송, 역할 중복, 심판 재접속·인계, 늦은 참가, 교체/MOM/종료 전파, 오래되거나 손상된 프레임 거부를 검증한다. 두 실제 브라우저 페이지를 개발 Realtime에 연결한 동작 검증도 수행한다.

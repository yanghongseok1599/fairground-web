# 연합팀 이벤트 중계

A조·B조 각 6개 원 참가팀을 같은 조 안에서 두 팀씩 묶어 연합팀 6개로 운영한다. 슈팅왕은 남녀 대표 각 1명, 공 살리기는 출전자 6명이다. 최고 배점은 슈팅왕 100점, 공 살리기 1,000점이다.

## 실행

개발 및 빠른 현장 리허설:

```sh
npm run dev:event
```

행사 당일에는 미리 빌드한 서버로 실행하는 편이 안정적이다.

```sh
npm run build
npm run start:event
```

시작 페이지: <http://localhost:3100/events/alliance>

- **새 이벤트 만들기**: 실제 행사 기록. 원 참가팀과 선수 이름을 직접 입력한다.
- **연습 이벤트 열기**: 가상 팀·출전자 명단 제공. `연습 기록 채우기`로 두 종목의 샘플 결과를 확인할 수 있다. 화면에 연습 표시가 남는다.
- **팀 편성**: 새 이벤트는 A/B조 각각의 6팀을 무작위로 섞어 같은 조 안에서 두 팀씩 묶는다. 총 6개 연합팀을 만들며 중복·누락 없이 저장한다. `랜덤 자동 배치`로 다시 추첨하고 `배치 저장`을 누르면 출력에도 반영된다. 저장 전에는 직전 추첨을 되돌릴 수 있다. 구성팀이 바뀐 연합팀의 출전자 명단은 비우고, 연합팀 이름은 유지한다. 이후 새 연합팀명, 남녀 슈팅 대표, 공 살리기 6명을 입력한다. 동명이인은 등번호로 구분한다. 시간/횟수 기준과 공개 시간을 선택한 뒤 저장·확정한다.
- **경기 진행**: 두 연합팀 선택 → 도전 선수 선택 → 측정값 입력 → `기록 저장 + 중계 공개`. 기본 4초 후 양 팀 비교로 바뀐다. `다음 차례`는 남녀 대표와 두 팀을 번갈아 안내한다.
- **공 살리기**: 시간 또는 횟수를 입력한다. 시간 방식에서는 운영자용 스톱워치도 제공한다. 판정과 시작·정지 조작은 사람이 담당한다.
- **종목 결과 확정**: 슈팅은 대표별 2회, 공 살리기는 팀별 2회 기록 완료 후 순위를 확정한다. 기록 동률이면 보조 기록을 비교하고, 여전히 같으면 순위 결정전을 시작한다.
- **종합 결과**: 두 종목을 모두 확정하면 우승 발표 버튼이 열린다.
- **기록 내역**: 원기록 정정·무효·다시 공개. 정정 시 해당 종목 결과와 의존하는 순위 결정전이 무효화되어 다시 확정해야 한다.

편성 확정 후 팀·출전자·규칙 변경은 잠긴다. 잘못 확정한 편성은 새 이벤트로 시작한다. 현재 버전은 원 참가팀과 출전 명단을 수동 입력하며, 기존 회원 DB에서 선수를 가져오지는 않는다.

## 출력과 다른 기기 연결

운영 페이지 `/events/alliance/{id}/control`과 출력 페이지 `/events/alliance/{id}/display`는 독립적으로 연결된다. 탭 사이의 localStorage 공유에 의존하지 않으므로 OBS나 다른 브라우저에서도 같은 기록이 나온다.

1. 운영 화면에서 **출력 화면 열기** 또는 **출력 주소 복사**.
2. OBS의 브라우저 소스에 주소를 넣고 **1920 × 1080**으로 지정.
3. 카메라 위에 얹으려면 **OBS 투명 주소**를 복사한다 (`?overlay=1`).
4. 현장 모니터의 브라우저는 출력 화면에서 **F 키** 또는 전체화면 버튼을 사용한다.
5. 다른 노트북·휴대폰은 같은 네트워크에서 `http://행사노트북IP:3100`에 접속한다. 운영 화면의 `다른 기기에서 입력·송출하기`에 이 주소를 입력한 뒤 필요한 링크를 복사한다. `localhost` 주소는 다른 기기에서 행사 노트북을 가리키지 않는다.

출력 링크에는 수정 권한이 없다. **운영 전용 링크**의 URL fragment에는 운영 토큰이 있으므로 운영 담당자에게만 전달한다. 처음 이벤트를 만든 브라우저는 운영 권한을 로컬 저장소에 보관한다. 운영 전용 링크를 보관하면 다른 브라우저에서도 이어서 운영할 수 있다.

기록 입력 중인 숫자는 전송되지 않는다. 저장이 성공한 기록만 출력하며, 출력 장면은 별도 스냅샷으로 저장한다. 최초 조회·재접속은 현재 장면과 서버 시각을 읽고, 기본 400ms 주기로 최신 상태를 확인한다. 공개 시간은 서버 타임스탬프 기준이므로 출력 창 새로고침으로 4초가 다시 시작되지 않는다. 연결 실패 시 마지막 화면을 유지하고 연결 확인 상태를 표시한다.

## 저장과 운영 범위

- **현장 노트북의 단일 서버**에서 실행하는 버전이다. 해당 서버가 켜져 있어야 다른 기기의 입력과 송출이 계속 연결된다.
- 원기록·편성·송출 상태는 `.local/alliance-events/{id}.json`에 저장된다. 서버를 재시작해도 복원된다. 이 폴더는 Git에서 제외했다.
- 다른 노트북으로 이전할 때는 서버를 종료하고 `.local/alliance-events/` 폴더를 통째로 복사하며 운영 전용 링크도 보관한다. 새 노트북 주소로 링크의 호스트를 바꾼다.
- `기록 백업`은 분석·보관용 JSON을 내보낸다. 이 파일을 가져오는 UI는 제공하지 않는다. 전체 운영 환경의 복구에는 위 저장 폴더와 운영 링크를 사용한다.
- 동시 요청은 파일 잠금과 revision 비교로 처리한다. 동일 request ID의 재시도는 중복 기록하지 않는다. 저장 결과를 알 수 없으면 동일 요청을 재확인하고 추가 입력을 막는다.
- 운영 토큰은 서버 파일에 SHA-256 해시로만 저장한다. 공개 조회에 토큰·내부 원기록을 포함하지 않는다.
- `FAIRGROUND_EVENT_LOCAL=1`일 때만 API가 동작한다. Vercel에서는 파일 보존을 보장할 수 없어 명시적으로 차단한다. 운영 웹사이트 배포·Supabase 마이그레이션은 수행하지 않았다.
- 행사장 내부 네트워크에서 사용한다. 인터넷 공개 서비스로 운영하려면 별도의 영속 DB·인증 배포가 필요하다.

## 판정 규칙

| 순위 | 슈팅왕 | 공 살리기 |
| ---- | -----: | --------: |
| 1위  |    100 |     1,000 |
| 2위  |     80 |       800 |
| 3위  |     60 |       600 |
| 4위  |     40 |       400 |
| 5위  |     20 |       200 |
| 6위  |      0 |         0 |

슈팅왕 팀 기록은 남녀 대표 각각의 최고 속도 평균이다. 평균이 같으면 유효 슈팅 기록을 높은 순으로 비교한다. 공 살리기는 두 번 중 최고 기록, 이어 나머지 기록을 비교한다. 여전히 같으면 동률 그룹 전체가 같은 조건으로 추가 도전한다. 슈팅 순위 결정전은 남녀 각각 1회, 공 살리기는 팀마다 1회이며, 그룹 전체가 완료되기 전에는 추가 기록으로 순위를 결정하지 않는다.

공 살리기 순위 간 차이 200점이 슈팅 최대 차이 100점보다 크므로, 단독 순위가 확정된 정상 경기에서는 최종 순위가 공 살리기 순위와 같다. 최고 합계는 1,100점이다.

측정 실패는 무효 처리하고 재시도한다. 현재 구현은 모든 팀의 정규 유효 기록을 요구하며 공식 기권·실격을 점수로 처리하는 기능은 제공하지 않는다. 기권·실격 운영안은 설계 문서의 후속 범위다.

## 파일 책임

- `types.ts`: 저장 데이터와 운영 명령
- `engine.ts`: 편성·기록 검증, 명령 처리, 출력 장면
- `scoring.ts`: 두 종목 순위, 동률·추가 도전, 합산 점수
- `pairing.ts`: 조별 무작위 추첨, 구성팀 변경 시 출전자 초기화
- `server/`: 파일 저장, 운영 권한, CAS·중복 요청, HTTP 입력 제한
- `client.ts`: 연결, 복원, 요청 재확인, 서버 시각 보정
- `setup-form.tsx`, `game-controls.tsx`, `control-page.tsx`: 운영 UI
- `broadcast.tsx`: 대기·준비·기록 공개·비교·순위·우승 그래픽
- `launcher.tsx`, `event.module.css`: 시작 화면과 스타일

## 검증

```sh
node --experimental-strip-types --test tests/alliance-event.test.ts
npm run lint
npx tsc --noEmit
npm run build
```

14개 자동 검증에서 무작위 편성의 중복·누락 방지, 편성 확정 후 변경 차단, 배점 조합, 남녀 대표 합산, 동률 결정전, 정정 후 결과 무효화, 재공개, 서버 복원, 중복 저장 방지, 운영 권한을 확인했다. 브라우저에서는 실제 속도 공개·4초 뒤 비교·화면 유지·새로고침·두 종목 확정·우승 발표·투명 배경과 현장 IP 주소에서의 저장을 확인했다.
